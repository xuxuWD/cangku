## 2. 权限模型：RBAC + ABAC 混合（三层，定死）

1. **RBAC（主体）**：角色 → **岗位能力包**（Skill / MCP / 知识库范围 / 记忆策略 / 自治档）⇒ 明细见 `role-templates.md`。
2. **ABAC（条件）**：`tenant_id`（**服务端从认证上下文注入，永不接受请求体传入**）+ `project_id`（项目）+ `数据敏感级别`（知识库 ACL，见 `knowledge-acl.md`）。
   **部门/组织维度：已裁决（2026-09-19）「暂不引入、留扩展位」** —— 第一期不落组织实体（避免空部门/假权限），
   但**数据范围必须写成可扩展枚举**（`tenant → project → 未来 org`），岗位绑定与模板**预留 org 字段位**；
   待身份源（LDAP/钉钉/飞书）接入时再落实体，届时**不需翻修权限模型**。依据：ADR-0004（含否决"立刻对齐"的理由）。
3. **交集规则（数字员工，一句话定死）**：
   `数字员工可用权限 = 创建者权限 ∩ 使用者权限 ∩ 岗位能力包`
   - **共享只是把更多人变成"使用者"，不改本式**（交集不会因为共享而变大）；
   - **禁止任何形式的权限放大**（含"临时提权""代跑""管理员代批"）。

### 2.4 每次校验必须重新检查的输入（12 项，逐字沿用知识库既有决策）

`用户 · 设备 · 租户 · 工作区 · 项目 · 数据范围 · 动作 · 外部目标 · 预算 · 授权有效期 · 审批状态 · 幂等键`

> 依据：`D:\徐徐AI学习\AI知识库\raw\sources\GEO\智曜GEO与数字员工工作台总体思路复审-2026-09-03.md` §三.3（原文逐字）。
> **铁律（原文）**：「前端隐藏菜单只能改善体验，**不能作为安全边界**」——所有判定必须在服务端执行。

### 2.5 高权限数字员工的边界（定死）

「高权限数字员工」= **在明确范围内的高自治**，不是无限权限。权限必须绑定：**时间 · 范围 · 预算 · 数据分类 · 外部账号 · 可回滚动作**（原文口径）。
⇒ 因此本矩阵的每个 ⚠️ 格子都要能回答"范围是什么、到期时间是什么、预算上限是多少、数据级别上限是多少、能否回滚"。

## 5. 权限校验的执行点（**每一处都是"逐行人工审核"对象**）

1. 路由层：`app/main.py` —— 认证 → 租户解析（服务端注入）→ 角色判定。
2. 服务层：各域 `ensure_*` 断言（任务/运行/技能/知识/商业化）。
3. **工具调用前**：`app/tool_execution/` 九步闸门 —— 每次 `tools/call` **独立授权**。
4. **知识检索前**：知识策略守卫（fail-closed：无绑定 ⇒ 空结果 + 审计，绝不放开）。
5. 数字员工运行：计划审批 → 执行授权位（`runtime` 域）。

## 6. 性能验收口径（补：原规范只写"≤5ms"未给测法）

- **口径**：单次**服务端**权限判定（不含网络）耗时 **P95 ≤ 5ms**；知识检索端到端 **P95 ≤ 2s**（含上游）。
- **测法**：① 单元级——对 `ensure_*` / 守卫函数做 10k 次内存调用取 P95；② 链路级——用审计时间戳差值对真实链路抽样（≥100 次）。
- **不达标处置**：先查是否引入 N+1（典型：每步查库取角色/绑定）⇒ 允许加**只读缓存**，但缓存失效必须走 ADR（涉及权限，不得随手加）。

## 8. 验收（可验证语句）

1. 租户 A 的任何请求都无法读到租户 B 的数据（含列表、详情、导出、检索四类入口）。
2. 普通员工调用管理类接口（权限配置 / 技能复核 / 审计导出 / 租户删除）一律 `403`。
3. 数字员工在"使用者权限 < 创建者权限"时，可用能力 = 两者交集（构造用例证明不放大）。
4. 知识检索对无绑定用户返回空结果且写审计（不返回 500、不静默返回他人文档）。
5. 权限判定 P95 ≤ 5ms（按 §6 口径实测并留证据）。

## 9. 第一期边界与角色分权（沿用知识库既有冻结结论）

**第一期只验证一个完整闭环**（原文口径）：
`岗位入口 → 数字员工理解需求 → 生成任务计划 → 权限/预算检查 → 执行 → 证据/结果 → 人工审批 → 任务完成或回滚`

- **首批试点**：自媒体运营 + CEO 看板（内部）；摄影剪辑、Vibe Coding **放后续批次**（需桌面桥接与更高供应链审查）。
- **不阻塞第一期**：应用商城、第三方 Skill、全量平台采集、本地视频大模型、完整客户 SaaS。
- **CEO 与超级管理员必须分权**：两个可审计角色、分级重认证，**禁止单一永久全能账号**（原文 §四）。
- **任务最小字段集**（每个任务都必须有）：唯一任务号、租户、项目、发起人、数字员工、风险等级、预算、幂等键、有效期、成功条件、失败原因、证据引用、审批记录、回滚状态（原文 §三.2）。
