## 浏览器走查手法（AntD `Select` 多选，2026-09-21 实测沉淀）

**结论**：AntD `mode="multiple"` 的 `Select` **对真人可用**；自动化工具"点不开"通常**不是产品缺陷**，而是三条手法问题：

1. **目标必须先在视口内**：页面若停在列表底部（如 `scrollY≈5300`），筛选项全是 `offscreen`，点击会落到别的元素上（实测落到了分页的 `<li>`）⇒ 先 `browser_scroll({ ref, scrollIntoView: true })`，并**核对 `scrollY` 与元素 `y`**。
2. **别点占位 `span`**：`.ant-select-selection-placeholder` 是 `pointer-events: none`（AntD 设计），工具会直接报错；**点它的 `<label for="<form name>">`** 即可——焦点会落到 `INPUT#<name>`（实测 `activeElement.id === 'actions'`）。
3. **多标签页时必须显式传 `viewId`**：不传会默认打到"最后交互的标签页"（实测把操作打到了另一个 tab）。

**选中与提交**（`rc-select` 标准键盘协议）：`↓` 移动高亮（`aria-activedescendant` 变化）⇒ `Enter` 选中（多选不关下拉，`Escape` 关闭）⇒ 点「查 询」⇒ 核对命中总数与当页列值。

**判据（区分"产品缺陷"与"工具限制"的最小证据集）**：`document.querySelector('#<name>')` 的 `disabled / tabIndex / role`、`.ant-select-selector` 的 `pointer-events`、`label[for]` 是否与控件 `id` 对齐、以及**能否用 `↓`+`Enter` 完成一次真实选中**。四项都正常 ⇒ 控件没问题，改手法不改代码。
