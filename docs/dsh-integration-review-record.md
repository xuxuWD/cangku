## 1. 结论

三个视角**一致认定：不予放行**。规格的整体方向被认定为正确（闸门先于执行器、黑名单为兜底而容器边界为主防线、无新迁移、承诺边界未夸大），但存在会**直接导致安全事故或实现无从落地**的缺陷，必须先修订并重审：

- 安全问题 2 条：授权位不含参数（「批准 A、执行 B」）、黑名单 `basename` 判定可被工作卷内同名可执行文件一步绕过。
- 文档互斥 1 条：`origin=conversation` 与「零新迁移」不能同时成立。
- 流程空洞 1 条：审批通过后如何推进到执行未定义。
- 幂等缺失 1 条：对话端点开始触发真实副作用却无幂等键。

## 4. 建议与待核实（合并三视角）

**容器与执行环境**
- 补：`--security-opt no-new-privileges`；工作卷 `nosuid,nodev,noexec`（`noexec` 兼作 B3 的第二道缓解）；mount propagation；`/dev/shm` 与 `/tmp` 可写可执行面；镜像按 **digest** 钉死；执行器崩溃后**孤儿容器回收**（「任务结束即销毁」只覆盖正常路径）
- 明确工作卷**设备隔离**与校验→执行的**原子性**（fd 传递 / `openat2 RESOLVE_BENEATH`）；补 TOCTOU 与硬链接用例（**待核实**：硬链接不改变 realpath，若与敏感文件同设备可绕过 ③ 与 C 类）
- 明确工作目录 **per-run 唯一性**、销毁时机、失败残留清理，以及跨租户不可见的证据判据

**黑名单与路径匹配**
- 明确 R1 规范化口径：长选项 `=`、短选项粘连、大小写归一；补齐等价别名与数值形态（`-P`、`0777`、`a+rwx`、`--reference`）；解包默认不跟随符号链接
- 明确 C 类**匹配算法**（realpath 绝对路径前缀 / 基名 glob / 是否大小写归一 / `~` 是否展开），补齐 `/proc/self/maps|mem`、`/proc/sys/**`、`/sys/**`、`/dev/**`
- R2 声称「兼容 Windows 侧 `pwsh`/`cmd`」不成立（未剥离 `.exe/.cmd/.bat/.ps1`）→ 要么补剥离，要么在规格里**限定本段只在 Linux 容器运行**

**流程与验收**
- 用例 4 的「必须红」**不可复现**（④ 挪到 ⑦ 之后仍在 ⑧ 之前）→ 观测点应改为「审批通过后的第二次执行尝试是否**重跑 ②③④**」
- 用例 2/8/10 的「必须红的方式」为空，需补具体改坏构造；用例 10 的「切回 mock 后全量全绿」无判定口径；§3.6 外置开关未给配置项名/取值/默认值
- §5 未覆盖已锁定决策点：Q4（启动期断言）、Y2、Y3（不落 args_digest 等）、§3.5 剖面锁死、超时=终止容器、`--cap-drop ALL`/pids/memory/无 `docker.sock`/容器无凭据
- 补一条**聚合测试命令**（等价 CI 四个 job），现无脚本落点；§6 的泛化条目不能替代用例
- 清单自认「最高优先级待验项」——`bash/write/edit` 的 `sandbox_permissions`/`justification` 升级通道真实行为（自动拒 / 挂住 / 静默放行）——在 §5 无用例，须列为段二-1 明确交付判据

**合规与流程**
- 许可证：14 个 LGPL（全为 `sharp`）与「一旦分发镜像/桌面产物即触发 LGPL 义务，须产出 `THIRD-PARTY-NOTICES`」应列为**交付物与验收项**，并明确本段是否分发镜像
- 环境分开：规格只写「与工作台分主机」，未写开发/测试/生产三套环境的程序/配置/数据/权限如何分开；清单 A2 的「开发期本机 Docker」与规格的无条件分主机约束不对称（F4 取证本身即在本机 Docker 完成）
- 收尾纪律：段二-2 的**一次性假执行器/测试桩**须纳入清理清单并经用户确认后删除
- 写代码与验收分离：四个子段的验收应明确由**只读独立方**执行
- 前端：对话页触发真实执行后，加载/空/错误/无权限**四态**与前端用例未纳入验收
- **待核实**：单会话最大轮次上限（宪法 4.9）由谁承担；模型/dsh 调用的重试上限与单次失败降级路径；真源三件套中「功能清单」是否齐备（若以立项文档 §14.1 充当，需显式引用）
