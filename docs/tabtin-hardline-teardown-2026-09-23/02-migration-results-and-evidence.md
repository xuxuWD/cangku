## §1 拆的是哪一块

TabTin 把「命令红线 / 绝对路径红线 / 敏感路径四态」三套安全规则放在一个 JSON SSoT 里，
但这份规则在仓库里**存在多份拷贝**，靠人工同步：

| 端 | 形态 | 为什么只能抄 |
| --- | --- | --- |
| TS `security-policy` | 直读 JSON | —（原始位置） |
| TS `terminal-core` | 构建期抄一份生成的 `.ts` | **依赖方向相反**，它不能反向 import `security-policy` |
| Python Django | 手抄成 `generated_hardline.py`（约 200 行） | 跨语言 |
| Python（第二处） | `authorization_policy.py` 又手抄一份 force 表 | 无人发现 |
| Python（第三处） | `generated_critical_rules.py` 再抄一份 | 孤儿文件 |

迁移目标：**让每条规则只剩一份可编辑定义，改一条规则只改一处。**
做法：把 SSoT 移到两端共同的中立依赖包，各端改为**运行时直读** + **fail-closed**。

## §3 ⭐ 最值钱的部分：10 处「原始判断被实测推翻」

这一节是本次拆解**最有复用价值**的产出。原清单是**静态审出来的**，逐条实跑之后，
**10 处结论站不住**。教训是一致的：**读代码得出的结论，必须实跑证伪一遍再动手。**

| 原判断 | 实测结果 | 标记 |
| --- | --- | --- |
| 某构建配置「catch 里吞掉拷贝失败」需修 | **已经修好了**（catch 里已有 `throw`） | ✅ |
| 某 `require.resolve` 会抛 `ERR_PACKAGE_PATH_NOT_EXPORTED` | 缺的是导出条件，**已补，问题不存在** | ✅ |
| 「`CRITICAL_DENYLIST` 缺 `curl-pipe-exec` = 漏洞」 | **不是漏洞**：该形态已被另一条规则拦下（实跑 4 种管道变体全部命中）。真正的问题在**相反方向** —— `redirect-write` 两端漂移，Python 侧会把合法命令误拦 | ✅ |
| 「某处 tier 硬编码应顺带改成派生」 | **改了是回退**：它复用的 slug 在 SSoT 里是低一级，派生会静默降级 | ✅ |
| 「Electron/Daemon 的拒读表是 SSoT 的拷贝，应并入」 | 是**独立且更严的一层策略**，并入会双向改行为 | ✅ |
| 「渲染进程的敏感片段表应对齐 SSoT」 | 那是**渲染进程的非权威预筛**，真正的闸门在主进程 —— 对齐它既不提升安全、又会丢掉本地独有的预筛 | ✅ |
| 「高危命令表去重同源条目」 | 语义与代码路径都**不同**，去重会让这些命令**失去审批触发**（该模块全文件不引用 hardline，没有兜底） | ✅ |
| 「本地敏感文件清单比 SSoT 严，派生会削弱」 | **`.aws/` 整目录其实已被 SSoT 覆盖**（原先只看了一个字段就下结论） | ✅ |
| 「把 vite 泛别名改成锚定正则是根治方案」 | 推广会打断 **3 个在用的子路径**，**已否决** | ✅ |
| 某文档提到的辅助脚本存在 | **不存在**（注释里的失效引用） | ✅ |

**共性**：这些错的都是「**从单一视角读代码后下的结论**」——只看了 `path_scan_rules` 没看
`sensitive_path_list`；只看了规则表没看**代码路径**；只看了注释没看**实现**。

## §4 验证方法（可直接迁移到任何「去拷贝 / 重构」任务）

本次能主张「零行为变化」，靠的是三步，**缺一不可**：

1. **改之前先固化旧行为快照** —— 把旧实现的规则/判定逐条 dump 成机器可比的形态。
2. **改完逐条 element-wise 比对**（条数 + 内容 + 顺序），而不是只看测试绿。
3. **真跑既有测试**，而不是只比对数据。

> ⚠️ 第 3 步不能省。本次**规则级比对完全没发现**一处丢掉的导出常量
> （它不是"规则"，所以规则比对看不见），是**跑真测试时 `ImportError` 报出来的**。
> 事后补做**完整公开 API 对比**才确认没有其他遗漏。
> **规则级比对 + 公开 API 比对 + 真跑测试，三者缺一不可。**

另外两条同样重要：

- **负向验证**：新增的每条守卫，都要故意注坏一次，确认它**真的会红**、且报错精确。
  「加了测试」不等于「测试有效」。
- **隔离变量**：测一个规则「缺了会怎样」时，用例必须**隔离**该变量。
  本次曾用 `/.ssh/id_dsa` 测某条缺失规则，两边都命中、看不出差异 ——
  因为另一条 `.ssh/` 规则先命中了；换到 `.ssh/` 之外的路径才暴露出真实缺口。

## §5 环境陷阱（换台机器就会重新踩）

| 陷阱 | 现象 | 标记 |
| --- | --- | --- |
| **构建产物状态会改变测试结果** | 同代码：某些包 `dist` 缺失时 7 files 失败，存在时 4 files 失败。**比对基线前必须先声明 dist 状态**，否则会把自己的构建产物误判成代码回归 | ✅ |
| **Windows 无法按预期建 Unix domain socket** | 一批用例报 `listen EACCES ...sock` | ✅ |
| **Windows 路径语义** | `resolve('/etc/shadow')` → `D:\etc\shadow`，正斜杠规则匹配不上 ⇒ 一批红线用例在 Windows 恒失败、在 Linux 通过 | ✅ |
| **测试套件抖动** | 同一份代码连跑三次得到 13/14/17 个失败；某些文件单独跑全过、并行跑超时 | ✅ |
| **构建顺序** | 大量包从未在本地构建过（84 个里 77 个无 `dist`），导致下游测试**整个文件加载失败**而非报错 | ✅ |
| **打包工具的 target 会剥掉新语法** | 老版本 esbuild 在 `target=es2022` 时把 import attribute 当新语法**静默剥掉** | ✅ |
| **宽松解析器不读 `exports` 映射** | 同一份导入：打包器能解析、tsc 报 `TS2307` —— 两边用的是不同的解析规则 | ✅ |
