## 4. 我方接入面（用于收敛 GEO 侧的交付范围）

### 4.1 最小接入面（第一期，来自《总体思路复审》§3.1）

第一期只验证一个闭环：**岗位入口 → 理解需求 → 生成任务计划 → 权限/预算检查 → 执行 GEO 或内容任务 → 证据/结果 → 人工审批 → 完成或回滚**。

据此，一期只需要 GEO 提供与下列环节对应的最小端点集（请 GEO 侧据 §3.1 填写对应项）：

1. 派发/创建 GEO 侧执行任务，并返回 GEO 侧任务标识；
2. 查询任务状态与进度（需支持顺序号/版本号，见 B8）；
3. 取回结果与**证据引用**；
4. 取消任务；
5. （如涉及）附件/产物的元数据读取。

> **暂不需要**（据《总体思路复审》§3.1、§5）：全量 14 个平台采集、自动发布、应用商城、模型直连。这些不应阻塞第一期。

### 4.2 事件与可靠性要求

据《总体思路复审》§3.2 与 §3.7，适配器需要：**顺序号、版本号、去重键、可重放**；不得只依赖轮询或各模块自行拼状态。请 GEO 侧说明事件/状态接口如何支持这四项。

### 4.3 「真实结果」分层口径（必须映射，不得合并）

据《总体思路复审》§3.6，以下状态在工作台侧**必须可区分**，若 GEO 侧把它们合并为一个状态，则适配器无法满足判据：

- 执行成功 / 已采集 / 证据已审核 / 可计入指标 —— 四者不同；
- 内容已批准 / 已进入发布队列 / 平台已发布 / 网址可访问 / 已通知搜索平台 / 已确认收录 —— 六者不同；
- 未配置、失败、样本不足、未提供排名、真实 0 —— **不得互相替代**。
