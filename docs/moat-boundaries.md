# 护城河与不可外包边界

> **性质**：**长期红线（立项级配套）**。回答一个问题：**哪些层绝不允许外包**，以及**什么情况下我们会变成"缝合怪"**。
> **触发**：2026-09-13 用户表态——「要自主可控、稳定、有自己护城河的公司级工作台；**不能是缝合怪、拼接怪，不能只会调用别人功能的连接器**；接受自研，开源能借鉴的借鉴、能搬的搬、接受魔改」。
> **依据**：[`architecture.md` §外部集成的判据](architecture.md)（三模式：接适配器 / 搬代码 / 只读研读）、[`multi-adapter-coexistence-spec.md`](multi-adapter-coexistence-spec.md)（共存规约）、立项文档 §1.3 / §14.1 / §15。
> **日期**：2026-09-13
> **配套**：[`capability-ownership-map.md`](capability-ownership-map.md)（能力归属表）——本文件说"**哪些不能外包**"，那份说"**每件事归谁**"。

---

## 1. 护城河的判据（三条，缺一不算）

| # | 判据 | 含义 |
| --- | --- | --- |
| **①** | **别人抄不走** | 不是"某个功能"，而是**多年积累的结构**（数据模型 + 治理规则 + 沉淀资产） |
| **②** | **越用越强** | 用一年后比用一天前更强：记忆、技能、审批规则、评测集**长在我们这里** |
| **③** | **拔掉外部引擎仍在** | 把 dsh / Codex / Hermes **全部拔掉**，产品**依然成立**（只是变笨），而不是归零 |

> **反例（不是护城河）**：模型能力、agent 主循环、浏览器驱动、沙箱运行时——**这些谁都能接**，你今天接 dsh，别人明天也能接，**不构成护城河**。

---

## 2. 四条**绝不允许外包**的层

| # | 层 | 为什么不可外包 | 现状 | 交付物 |
| --- | --- | --- | --- | --- |
| **M1** | **治理层**：多租户隔离（写进数据库约束）+ 岗位/权限模型 + **九步闸门** + 授权位 + **append-only 审计** | 这层是**开源生态的集体空白**（我们调研原话：「所有 agent 框架连『用户』概念都没有」）；一旦外包给引擎自带的权限模型，就出现**多套审批口径**，且**租户隔离与审计不再可信** | 段一已交付（四档风险 + 授权位 + 常驻外壳）；段二在规格中（**未开工**） | 段二规格 §3.2 / §3.2.1 / §4.1；`migrations/026`、`027`（待落地） |
| **M2** | **沉淀层**：记忆（P3）+ 技能（P4）+ 自进化（P6） | 这是**判据②「越用越强」的唯一载体**；外包 = 用户的记忆与技能**长在别人那里**，换引擎就带不走 | 🔴 **全部未开工（当前最大缺口）** | 立项 §14.1 的 P3/P4/P6 |
| **M3** | **业务模型**：**人 + 数字员工**的岗位 / 汇报 / 审批 / 协作编排 | 这是本项目**唯一不可被开源项目替代**的部分（别人的框架里没有"岗位""汇报线""审批阈值"这些概念） | P1 已交付（对话层 + 数字员工配置 + 岗位目录）；协同/任务/审批已交付 | 立项 §4 的 D8/D19–D23、`migrations/022`、`023` |
| **M4** | **可信交付**：可审计 / 可回滚 / 可解释 + **评测集** | "敢让数字员工碰真业务"的前提；评测集（golden set）是**用真实历史积累**出来的，别人复制不了 | 审计与回滚部分已交付；**评测集未做** | 立项 §15 #2；P6 的评测集口径 |

> **判定口径**：任何提议，只要它要求把 **M1–M4 中的任一层**交给外部（引擎自带权限、外部记忆库、外部技能市场、外部审计系统），**一律拒绝**，除非走**专项评审**并明确"为什么自研不成立"。

## 3. 允许"外包"的三类（**把轮子和引擎分开**）

| 类别 | 判据 | 该怎么做 | 例子 |
| --- | --- | --- | --- |
| **① 通用轮子** | 是**行业标准的库/协议**，不是产品 | ✅ **直接用**（不重复造轮子） | FastAPI / Pydantic / httpx / Playwright / OpenTelemetry / electron-builder / Tauri / PostgreSQL+pgvector |
| **② 窄组件** | 许可可商用 + **无状态/窄功能** + 进程边界传不过去 + 我们愿长期维护 | ✅ **可搬（vendor）**——**但当前无已生效实例** | **候选（未经评审、未启用）**：OpenClaw 的 `computer-use` 脚本集（MIT；若 vendor 须连带核对 `THIRD_PARTY_NOTICES.md` 并产出我方 `THIRD-PARTY-NOTICES`）；xdotool 封装类。**R5-8 更正**：原表述为"✅ 可搬"示例，与 [`architecture.md`](architecture.md) §外部集成的判据"② 无已生效实例"**互斥**，现统一为"无已生效实例 + 唯一候选" |
| **③ 整套引擎/平台** | 是"能自己干活的 agent/Harness" | ⛔ **接适配器 或 只读研读**，**不搬** | dsh / Codex / Hermes / DeerFlow / OpenClaw Gateway / EvoFlow |

**判定顺序**：先问"我要的是**能力**还是**代码**"→ 再问"它是**轮子**、**窄组件**还是**引擎**"→ 三问判据见 [`architecture.md`](architecture.md)。

> ⚠️ **"能搬就搬"的正确范围只有第 ② 类。** 把第 ③ 类搬进来（哪怕许可允许）**也不会带来护城河**——你拥有的仍是别人的引擎，只多了分叉与维护成本。

## 4. "缝合怪"自检清单（6 条，任一为"否"即已在退化）

| # | 检查项 | 合格标准 | 现状 |
| --- | --- | --- | --- |
| 1 | **领域模型** | 外部引擎的类型**不得进入**我们的领域模型 | ✅ 已定（dsh 细节封在适配器内） |
| 2 | **接口** | 只有**一套契约**（`AgentRuntimeAdapter`），新增引擎不改控制平面 | ✅ 五类 Runtime + mock 并存 |
| 3 | **执行入口** | 只有**一个**（九步闸门），不允许第二条绕过路径 | ✅ 段二已定"执行入口唯一" |
| 4 | **审计** | 只有**一套** append-only 审计；引擎自带的审计/日志**不作为事实源** | ✅ 已定（`reason` 受控枚举 + 明细白名单） |
| 5 | **数据** | 只有**一套**数据模型 + 迁移链；外部状态不回写我们的库 | ✅ 迁移链 `001–026`（`027` 待落地） |
| 6 | **界面** | 用户**看不出**"这块是 A 家的、那块是 B 家的"——**外壳自研** | ⚠️ **待 P2c**（当前 11 个平级页，尚未做对话主轴） |

## 5. 红线（写死，避免反复讨论）

1. **不搬第 ③ 类（引擎/平台）的代码**——包括许可允许的 Codex（Rust 内核）；
2. **不抄任何外部产品的界面外观**（WorkBuddy / Trae 闭源，EvoFlow 非商用）——**只借信息架构与交互模式**，页面**自研**；
3. **不接非商用/强传染许可的项目运行**（EvoFlow、OpenWorkBuddy）——**连接都不接**，只读研读；
4. **不让外部引擎自带的权限/审批/审计成为我们的放行依据**（`multi-adapter-coexistence-spec.md` 的 **I2**）；
5. **不为"抄近路"牺牲 M1–M4 的任一层**——**这四条是护城河本身**。
