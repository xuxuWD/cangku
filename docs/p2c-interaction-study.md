## 2. 对方的产品形态事实（引其 README 原文要点，不改写）

**OpenWorkBuddy（主要参照）**
- 定位：「一个真吐文件的本机 AI 办公 agent……交给你的是能直接打开的 PPT / Word / Excel / 网页，**不是一段聊天记录**」；「声称写了文件却不在磁盘上，会被当场拦下重做」。
- **四种工作模式**：Ask（只问答）/ Plan（只出计划）/ Goal（目标驱动 + 自动验收）/ Craft（完整执行）。
- **执行过程呈现**：「执行过程一行流：每步一行，原始入参和完整返回收在卡里点开就是」；「任务完成不再弹面板抢版面，产出收成一排 chip」。
- **权限与闸门**：「命令审批、文件黑名单、URL 白名单、审计日志、**四档权限**」；组织级开关**真的会在工具定义层拦人**——「关掉 `allow_shell`，`run_shell` / `run_node` 在工具定义层就被摘掉了，**模型压根看不见**」。
- **收尾闸门**：「收尾前对一遍进度档，还有没打勾的就打回去」；定时任务有「**假绿**」裁定——「没抛异常不等于干成了」。
- **部署形态**：桌面（macOS / Windows）+ `deploy.sh` 服务器部署，**支持多租户 + 企业管理后台**（成果文件 / 会话 / 账号 / 席位 / 用量账本 / 审计各租户互不可见；引擎与 API Key 归平台管理员）。
- **其余**：侧栏分「办公 / 工程」两条线；首装五步向导（注册 → 粘 Key **当场验活** → 选引擎）；技能 = 往 `skills/` 丢一个 Markdown，存盘即生效；长回复流式（十万字 DOM 重建 19.7s → 0.7s）；`wb` CLI 支持管道与 `--json` NDJSON、退出码如实。

**OpenMausBot（次要参照）**
- 定位：「your own team of AI bots, in a chat app」；侧栏每个 bot 是一个真实 agent（本机 Claude / Codex / Grok CLI），像**联系人**一样管理（置顶 / 未读 / 复制 / 隐藏）。
- **Bots ask before they act**：shell 命令、文件修改、提问以**内联卡片**出现，Allow / Deny / 直接回答；「a permission broker turns every risky action into a decision you make」。
- 每个 bot 有独立模型选择器（provider rail，**不可用项灰显并给原因**）；Computer 面板（每个 bot 一台电脑，可看实时画面、可接管）；Channels（工作 / 个人 / 项目分开，各有独立 transcript 与 working folder）；密钥**只写不可读**（UI 只显示"已配置"）。

## 3. 与我们现状的对照（差距性质沿用立项 §17.1 口径）

| 维度 | 我们现状 | 对方做法 | 差距性质 |
| --- | --- | --- | --- |
| 主轴 | 11 个平级页，对话只是其一 | 对话即主轴，bot/任务像联系人 | **界面**（D14 → P2c） |
| 过程呈现 | 只有「运行详情」一页静态概览 | 每步一行 + 原始入参/返回收在可展开卡 | **后端契约**（P2b 过程事件）+ 界面 |
| 产出呈现 | 整页导航，看不到「边聊边出产物」 | 产出收成一排 chip，点开即验收 | **界面**（D14 → P2c） |
| 审批 | 独立审批页 + 审批聚合 API | **对话内联 Allow/Deny 卡片** | **界面**（可复用既有审批 API，见 §4-A） |
| 权限呈现 | 白名单在服务端，前端只说"非法键" | 「模型压根看不见该工具」这种可解释口径 | **界面文案 + 口径**（低成本） |
| 收尾判据 | 有验收纪律（验收只认证据） | 「进度档未打勾就退回」「假绿裁定」 | **流程/界面**（P2c 起） |
| 模型选择 | `model_key` 自由文本 + 后端 422 | 选择器 + **不可用项灰显并给原因** | **界面**（P2c） |

> **三处描述更正**：① **A** 的决议形态是「**接管输入区**」而非卡上按钮，且走独立 `respond` 端点（与我方"前端只是入口、不新增后端契约"需在 P2b 选路）；② **F** 的形态是「**一个聚焦动作 + 原因 + 整屏 setup 态**」，不是灰显墙；③ **G** 的性能数字 **未在 OpenMausBot 复现**（属 OpenWorkBuddy 宣称，且 OpenMausBot **当前并不渲染增量正文**），我们的阈值须自定。

| # | 借鉴点 | 对方做法（原文要点） | 落到我们哪里 | 阶段 | **不照搬** | 验收判据（P2c 开工后适用） |
| --- | --- | --- | --- | --- | --- | --- |

| **B** | **执行过程"一行流" + 可展开卡** | 「每步一行，原始入参和完整返回收在卡里点开就是」 | P2b 过程事件 → 右舞台/对话内的步骤行 | **P2b 定契约、P2c 呈现** | 不照抄其行样式；**原始入参不得含敏感字段**（我们审计口径更严） | 每步可见且可展开；明细不含正文/凭据（宪法五道防线） |

| **E** | **收尾闸门的"未打勾就退回"** | 「收尾前对一遍进度档，还有没打勾的就打回去」 | 与既有验收纪律（只认证据）对齐的任务收尾检查 | P2b/P2c | 不引入"自动判分"（属 P6） | 未完成的收尾不可标记成功 |
| **F** | **模型选择器：不可用灰显 + 给原因** | 「不可用项灰显并给原因」 | 数字员工/会话的 `model_key` 选择 | P2c | 我们仍**以后端校验为准**（前端只是提示，不构成权限） | 非法/停用模型仍由服务端拒绝 |
| **G** | **性能判据：长流式不卡** | 十万字流式：DOM 重建 19.7s → 0.7s | P2b/P2c 的前端性能判据（长会话/长过程事件） | P2c | 不引入其实现 | 长会话滚动/追加不出现秒级卡顿（给具体阈值） |
| **H** | **域名白名单的边界比对** | 「白名单 `example.com` 不会顺带放行 `evilexample.com`」 | **将来**若开放受控抓取（属 P4/P5）时的校验口径参考 | P4/P5（本段无关） | 本段仍是 `--network none`，**不因此放开网络** | 仅作登记，不在本段实现 |

## 5. 明确不借清单（照搬会出事）

1. **外观与皮肤**：任何配色、布局像素、图标、动效、皮肤、文案一律不参照（PolyForm + 外观版权 + 立项 P2c 明令）。
2. **代码与资源**：不 clone 进本仓库、不复制文件、不引入其依赖。
3. **"每 bot 一台电脑/云桌面"的资源模型**：我们是多租户服务端，资源与合规边界不同 → 只借「面板呈现」，不借资源模型。
4. **一键接入数百个外部应用（第三方 SaaS 聚合）**：会引入外部凭据与数据出境问题，属 P4/P5 的独立评审范围，**不得顺手加**。
5. **CLI（`wb` 式）**：不是本阶段目标；如将来要做，须单独立项。
6. **"自动判分 / 自动验收"**：属 P6 口径，本阶段（含 P2c）不做。
