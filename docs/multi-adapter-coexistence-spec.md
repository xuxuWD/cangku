# 多适配器共存规约

> **性质**：**规约（草案 · 待评审）**。把"多个外部 Runtime 混用时如何不打架"写成可检查的规则。
> **触发**：2026-09-13 用户提问——「适配器相互之间的能力、功能是否能配合好，会不会搭配有冲突」。
> **上位**：[`architecture.md` §外部集成的判据](architecture.md)（接适配器 vs 搬代码）、[`runtime-onboarding-request.md`](runtime-onboarding-request.md)（对接契约与索取表）、段二规格（dsh 接入）。
> **日期**：2026-09-13
> **现状前提（重要）**：**当前生产路径只有 `mock`**；五类外部 Runtime 属 **POC 登记**，**真实 staging 联调未验收**（`delivery-readiness-checklist.md` 对应项仍为 ⬜）。故本规约**现在就能建立、但真正生效是在接入第一个真实 Runtime 之时**。

---

## 1. 适用范围

| 对象 | 角色 | 接入形态 |
| --- | --- | --- |
| `mock` | 默认（P1 起） | 进程内 |
| DeerFlow | 通用长任务候选 | 独立进程（HTTP） |
| Codex Worker | FDE 执行候选 | 独立进程（HTTP） |
| Hermes（`NousResearch/hermes-agent`） | 成长能力参考 / 隔离 Worker | 独立进程（HTTP） |
| RAGFlow | 知识层适配器 | 外部服务（HTTPS + 认证注入） |
| AgentScope | 受控执行器 | 外部服务（HTTPS + 认证注入） |
| `dsh` | 段二真实工具执行（**未接入**） | 适配器内部封装 |
| WeKnora | 企业知识服务 | 适配器（`architecture.md`） |

> **前提事实**：**适配器之间不互相调用**——每个 adapter 只与「自己的外部进程」和「我们（控制平面）」交互。因此不存在"接口对不上"的直接冲突；**冲突全部发生在共享面上**（能力、事件、资源、审批、版本）。

## 2. 六条不变量（违反即视为缺陷）

| # | 不变量 | 说明 | 现状 |
| --- | --- | --- | --- |
| **I1** | **一个任务只由一个 Runtime 承接** | 同一 `run_id` 不得在两个 Runtime 间接力；切换 Runtime = 新建 run | ✅ 靠调用方约定；**未写进契约** |
| **I2** | **审批口径唯一：外部原生审批一律不采用** | 任何外部引擎自带的审批/权限提示（Codex 沙箱审批、dsh profile、OpenClaw permission broker 等）**不得**作为我们的放行依据；放行只认我们的闸门与授权位（`026`/`027`） | ⚠️ **只对 dsh 写了**（段二规格 §2.1）；需扩为**对全部 adapter 的硬规则** |
| **I3** | **未知事件不得冒充失败**（**作用域见下方边界声明第 2 条**） | 外部事件名不在映射表内时，落**独立的"未知事件"类型 + 审计**，**不得**记为 `RUN_FAILED` | 🔴 **对既有实现为「不符合」，但本条不构成对既有已交付行为的改动要求**——现状 `app/runtime/adapters/common.py:140` 未知事件 → `RUN_FAILED`，与 `api-contract.md:606`「未知事件统一映射为 `run.failed`」**同向一致**；**任何提升须走「先改契约 + 影响评估」**（宪法 4.2 / 铁律四），**不得由本规约文件直接驱动** |
| **I4** | **能力必须声明且被消费** | 能力以**结构化声明**为准；**未声明 = 不支持**；闸门与 UI 读同一来源（不得"显示转不动的旋钮"） | 🔴 **当前缺**：`health().capabilities` 仅字符串透传，无人消费 |
| **I5** | **run → 外部 run 映射必须可持久** | 该映射不得只存在于进程内存；否则多 worker/重启即丢 | 🔴 **当前违反**：`ExternalAdapter._runs` 为进程内 dict |
| **I6** | **契约版本显式，不兼容即 fail-closed** | 每个 adapter 声明契约版本与兼容窗口；不兼容时**拒绝装配并告警**，不得静默降级 | ⚠️ **当前缺**：版本只固定外部服务版本，**adapter 契约本身无版本** |

**边界声明（R5-9 新增，定死；三条）**：

1. **本文件是「草案 · 待评审」**——**不得作为放行依据**，**不得作为改动既有已交付组件的依据**。`architecture.md` §外部集成的判据对本文件的引用**已降级为「参考（非强制入口）」**（该节已有状态声明；J-13 已把原祈使句改写，本条同步更新以免指向已不存在的表述）。
2. **I3 与既有契约同向但不等效**：`api-contract.md:606` 明写「未知事件统一映射为 `run.failed`」，实码 `app/runtime/adapters/common.py:140` 亦如此——**既有行为符合既有契约，问题只是"标准更高"**。**提升标准的唯一合法路径**：先改契约（§「改接口先改文档」）→ 做影响评估 → 按铁律四（改稳定组件需专项评审）执行；**禁止以本规约文件直接驱动改动**。
3. **I1/I2/I4/I5/I6 的"当前缺/当前违反"是事实登记**，不是"立刻修改"的要求：其中 I4/I5/I6 属**新增能力**（不破坏既有行为），可在后续段次实现时按本规约执行；**I1/I2 的收口方式（写进契约 / 扩为全 adapter 硬规则）须单独评审**。

## 4. 职责归口表（**一个任务类型 → 唯一承接 Runtime**）

| 任务类型 | 唯一承接 | 状态 |
| --- | --- | --- |
| 对话触发的内容/研究长任务 | DeerFlow | POC 登记 |
| FDE 交付（受限文件范围） | Codex Worker | POC 登记 |
| 成长 / 记忆 / 技能**提案**（不得写生产配置） | Hermes | POC 登记 |
| **企业知识检索** | **WeKnora（唯一主源，D1 已裁决 2026-09-15）**；RAGFlow 降为对照/实验（默认关闭） | ✅ **已归口** |
| **受控执行 / 工具执行** | **dsh（唯一真实执行路径，D2 已裁决 2026-09-15）**；Codex Worker 仅承接 FDE 交付；AgentScope 降为实验 | ✅ **已归口** |
| 默认（未指定） | `mock` | ✅ |

> **规则**：同一任务类型**只能有一行**。新增 Runtime 时，**必须先改本表**，否则视为未接入（防止"两个引擎抢同一类任务"）。

## 5. 冲突处理规则（逐类）

| 冲突类 | 规则 | 落点 |
| --- | --- | --- |
| 能力缺失 | 返回 `RuntimeUnavailable`（"已注册但当前不支持"），**不得静默退化为其他 Runtime** | 已有异常类型 |
| 事件未知 | 落"未知事件"类型 + 审计（**I3**）；不得记 `RUN_FAILED` | ⚠️ **须走「先改契约 + 影响评估」，不得由本规约驱动**（边界声明第 2 条；J-3 更正） |
| 资源重叠 | 以 §4 归口表为准；未归口的按"**拒绝**"处理（fail-closed） | D1 ✅ 已定（WeKnora 唯一主源）；D2 ✅ 已定（dsh 唯一执行路径） |
| 审批 | 只认我方闸门（**I2**）；外部原生审批不得作为放行依据 | 待扩为全 adapter 硬规则 |
| 版本不兼容 | 拒绝装配 + 告警（**I6**）；不得"尽力兼容" | 待补 |
| 并发与预算 | 同一租户并发运行数、预算汇总口径**当前未定义** → 登记为 **D3**；在定义前**不得声称"预算可控"** | 待裁决 D3 |
| 状态丢失 | run 映射必须可持久（**I5**） | 待改/待裁决 |

## 9. 未核实与不做

**未核实**：① §3 表中所有"未核实"格——对方是否真具备该能力**未取证**；② 五个外部 Runtime 的许可**未逐个核**（见 [`poc-license-checklist.md`](superpowers/poc-license-checklist.md)）；③ 外部 Runtime 是否遵守我们传入的 `budget_cents`（**未取证**）；④ `RuntimeUnavailable` 在各 adapter 的实际覆盖情况（仅确认异常类型存在）。

**不做**：① 不为"可能的冲突"提前重写现有 adapter；② 不改 P2a→P2b→P2c 顺序；③ 不在本规约中决定 D1–D3（属用户/评审裁决）。

> **与既有文档的关系**：本规约是 [`architecture.md` §外部集成的判据](architecture.md) 的**配套细则**（判据管"要不要接"，本规约管"接了之后怎么共存"）；接口细节以 [`api-contract.md`](api-contract.md) 与 [`runtime-onboarding-request.md`](runtime-onboarding-request.md) 为准，本文件**不复写**。
