## 0. 结论先说（两个前置发现）

### 发现一：项 7 的平台 = **微信公众号（公众号）**，本仓库已钉死

`docs/external-dependency-acceptance-plan.md` §5 输入清单原文：

> | 6 | 真实平台账号（**公众号**）与发布授权、回执核对人 | 7, 9 |

**因此项 7 要索取的是「微信公众号」的账号与接入资料**，不是那些媒体发稿供应商。

### 发现二：工作台的发布器**不是微信原生 API 封装**，而是自定义端点协议

这一点比"没有账号"更前置。`app/content/publisher.py` 的 `WechatMpPublisher` 说的是**工作台自定义的协议**（详见 §1），它**不包含**：appid/appsecret 换取、access_token 生命周期、封面永久素材上传、草稿与发布接口、IP 白名单处理。

**所以「接入文档」有两个可能的供方**，必须先定是哪一个（见 §4）：

- **路径 A**：由一个中间网关按工作台协议提供端点 —— 需要**网关方的接口文档**；
- **路径 B**：我方新增**公众号原生适配器** —— 这是**真实代码缺口**，需要官方文档 + 账号权限（见 §3）。

## 1. 工作台侧实际协议（读代码得出，精确）

来源：`app/content/publisher.py`（`WechatMpPublisher`）、`app/bootstrap.py`（`build_content_publisher`）、`.env.example`。

### 1.1 配置项（已存在，名称以下列为准）

| 配置 | 说明 |
|---|---|
| `WORKBENCH_CONTENT_PUBLISH_TARGET` | 目标标识，默认 `wechat_mp` |
| `WORKBENCH_CONTENT_PUBLISH_ENDPOINT` | 端点基址 |
| `WORKBENCH_CONTENT_PUBLISH_ACCOUNT_ID` | 账号标识 |
| `WORKBENCH_CONTENT_PUBLISH_ACCESS_TOKEN` | 访问令牌（**密钥，仅经部署密钥系统注入**） |
| `WORKBENCH_CONTENT_PUBLISH_TIMEOUT_SECONDS` | 超时，默认 15 |

**fail-closed**：三项（endpoint / account_id / access_token）任一为空 → 发布功能整体关闭（`build_content_publisher` 返回 `None`）。

### 1.2 发布协议

**发布**：

```
POST {endpoint}/publish
Authorization: Bearer {access_token}
Content-Type: application/json

{ "title": "...", "content": "...", "idempotency_key": "任务号:版本", "account_id": "..." }
```

**响应要求（必需字段）**：2xx + JSON，且**必须包含 `receipt_id`**；可选 `status`（默认 `succeeded`）。缺 `receipt_id` → 判定发布失败。

**回执核对**：

```
GET {endpoint}/publish/{receipt_id}
Authorization: Bearer {access_token}
```

**响应要求**：2xx + JSON，**必须包含 `status`**。

### 1.3 行为约束（安全设计，供方必须配合）

- 幂等键为 `任务号:版本`（迁移 `016` 有唯一约束），**重复提交不得重复发布**；
- 发布失败 → **转人工接管，绝不自动重发**；回执核对失败同样如此；
- 传输层任何异常、非 2xx、响应不可解析，一律判失败。

## 2. 公众号官方发布链路（已核实，附官方链接）

来源：[微信开放文档 · 服务端 API](https://developers.weixin.qq.com/doc/service/api/)、[新增草稿](https://developers.weixin.qq.com/doc/subscription/api/draftbox/draftmanage/api_draft_add)、[草稿箱能力页](https://developers.weixin.qq.com/doc/subscription/guide/product/draft.html)、[媒体API文档](https://res.wx.qq.com/download/MediaApiDoc.pdf)。

| 步 | 接口 | 要点 |
|---|---|---|
| 1 | `GET /cgi-bin/token`（或 `/cgi-bin/stable_token`） | 获取接口调用凭据 **access_token**，**有效期 7200 秒**，需自行缓存与刷新 |
| 2 | `POST /cgi-bin/material/add_material?type=image` | 上传封面图得**永久素材** `media_id`（草稿封面必需） |
| 3 | `POST /cgi-bin/draft/add` | 新增草稿 → 返回草稿 `media_id`；必填 `articles[].title`（≤32 字）、`content`（HTML，≤2 万字符、<1MB）、`thumb_media_id` |
| 4 | `POST /cgi-bin/freepublish/submit` | 提交发布 → 返回 **`publish_id`**；**异步**，需另查发布状态 |

### 2.1 硬约束（决定项 7/9 能不能做）

| # | 约束 | 影响 |
|---|---|---|
| W1 | **IP 白名单**：未把调用方服务器 IP 加入白名单会报 `errcode 40164 invalid ip` | 需要把 staging/生产出口 IP 报备到公众号后台 |
| W2 | **发布接口权限与账号类型绑定**：草稿接口订阅号/服务号均可调用；**发布接口 `freepublish/submit` 对公众号（原订阅号）仅"已认证的企业主体账号"可调用** | **若账号是个人主体或未认证企业主体，项 9 的"自动发布"根本无法验收** |
| W3 | 发布为异步，需查询状态才能确定结果 | 与工作台"回执核对"语义需要映射（`publish_id` ↔ `receipt_id`） |

> **W2 需以官方页面逐字核实**：该条整理自官方能力页与第三方技术笔记，**具体权限口径请在账号侧以公众号后台与官方文档确认后再据此排期**，不要据本文件下定论。

## 4. 两条落地路径（需先定一条）

### 路径 A：由中间网关按工作台协议提供端点（**无需改工作台代码**）

网关负责：access_token 生命周期、封面素材上传、草稿、发布、状态查询、IP 白名单维护。我方只对接 §1.2 的协议。

**需要索取**：网关的接口文档（确认它确实按 §1.2 的实现）、它的认证方式、错误语义、幂等键支持。

> **注意**：`WORKBENCH_CONTENT_PUBLISH_ENDPOINT` 目前**没有对应的实现方**——这是路径 A 的真实缺口：**协议是我方定义的，但没有任何一方声明实现它**。

### 路径 B：我方新增公众号原生适配器（**代码缺口**）

若由工作台直连微信 API，需新增：`token` 缓存与刷新、封面素材上传、`draft/add`、`freepublish/submit`、发布状态轮询，并把 `publish_id` 映射为工作台的 `receipt_id`。

**需要先确认**：P1（账号权限）、P2、P4。

> **本文件不预写该适配器代码**，待路径定案与账号权限确认后再实现（参照仓库既有纪律：拿到契约/权限前不做占位实现）。

## 5. 安全红线（与仓库既有纪律一致）

1. AppSecret / access_token **只经部署密钥系统注入**，禁止提交进仓库、聊天、邮件或工单正文；
2. **不得入库、不得入日志、不得入审计明细**；发布响应中的凭据字段同样不得落库；
3. 账号权限**最小化**：先只读、再草稿、最后才发布；
4. 项 7 的验收动作**不含发布**（只做一次不产生外部副作用的只读调用）；发布动作在项 9；
5. 失败一律**人工接管，绝不自动重发**（工作台已有幂等键与唯一约束，供方需配合幂等）。

## 6. 边界澄清：软文云 / 思默 / 媒介盒子**不属**本项

知识库有一份《媒体平台 API 可接入性调研-2026-09-04》，评估了软文云、思默 AI、媒介盒子、KOLRANK、媒介集市等。**那是智曜 GEO 的媒体采购供应商，不是本工作台的平台账号。**

依据：

1. 该调研原文写的是「**智曜 GEO** 真正需要的核心能力」，并称「**智曜 GEO** 只有在取得接口文档、测试账号、商务授权和合同后，才能把某个平台列为正式对接渠道」——主语是 GEO；
2. 本仓库内检索 `软文云`、`思默`、`媒介盒子`、`KOLRANK` → **无任何匹配**；
3. 工作台侧的发布能力只有 `WechatMpPublisher`（公众号），职责边界（`README.md`「与 GEO 的边界」）把媒体采购与发布供应链划归 GEO。

**触发重审的条件**：若产品要求工作台直接对接媒体发稿平台（而非经 GEO），须**另立条目并先做边界评审**——与 GEO 供应商（DeepGEO 等）的处置口径一致（见 `docs/geo-contract-request.md` §0）。
