## 3. 数据模型（**引用 B1 规格 §3，此处只列 B2 特有的差异**）

**B1 规格 §3.3 已定**：`owner_user_id` + `visibility` + `workbench_employee_shares`（两档 `read`/`use`）+ 四档可见性口径 + 迁移影响面。**本文不重写。**

**B2 特有的两点**：

### 3.1 现有 `autonomy_level` 的语义要澄清

现有三档（迁移 `023`）：`approval_for_all` / `approval_for_risky` / `full_auto`。

**本文明确**：
- 这三档**只约束「派活之后的执行是否要人批」**，**不表示"自主发起"**
- **本期没有"自主发起"**（见 N4）
- ⇒ 建议在 `api-contract.md` 与界面上把这一档的文案从"自治等级"改为**更准确的表述**（如"执行审批档"），**避免用户误以为它在控制"主动性"**

**⚠️ 这是口径变更，须在契约里写明。**

### 3.2 岗位模板的存放位置

**建议：代码内常量**（`app/workforce/role_templates.py`），**不建表**。

**理由**：模板是**产品预设**，不是用户数据——改模板应走**代码评审**而非 DB 更新。若建表，任何人都能改模板，反而绕过了评审。

**⚠️ 但有一个例外要考虑（见 §9.1 V2）**：若将来允许**租户自定义岗位**，则需建表。**本文按"6 类固定岗位"设计。**

## 4. 创建流程与岗位模板

### 4.1 创建流程（五步，**借 EvoFlow `preset-role-assistant` 的设计**）

> **素材说明**：EvoFlow 是 PolyForm Noncommercial ⇒ **只读研读、只借设计**。其 `preset-role-assistant/SKILL.md` 定义了「创建角色」的强制顺序，**该顺序值得抄**（是设计，不是代码）。

```
① 澄清需求（先问再写）
   至少确认：这个数字员工**服务谁** / **典型任务 2~3 个** /
   **输出形态** / **绝对不做的事** / **是否需要联网·终端·文件写入**
   ★ 目的：防止用户随口建一个空壳

② 确认 agent_key 可用
   小写 + 连字符；不与已有冲突

③ 盘点技能（只从真实目录勾选）
   ★ 禁止臆造技能名——名称必须来自运行时目录

④ 盘点工具（**最小权限**）
   ★ 原始设计的原话：能只读就不给写盘，能不用终端就不给

⑤ 起草并让用户确认
   落盘前展示完整配置
```

**⚠️ 与 EvoFlow 的关键差异**：EvoFlow 把这个流程做成了**一个 Skill（给 LLM 看）**，而本文建议把它做成**界面上的向导**（`CreateAgentDrawer`）。

**理由**：用户的客户端是**桌面为主的人机界面**，不是纯对话；**表单向导比对话更能保证"该问的都问了"**。两者可并存（向导为主，对话为辅）。

### 4.2 护栏（三条硬约束）

| # | 约束 | 落地方式 |
| --- | --- | --- |
| **G1** | **名称必须来自真实目录** | 服务端校验 `skills` / `tools` 字段的每一项都在运行时目录内；**不合法则拒绝**（不是忽略） |
| **G2** | **最小权限默认** | 新建时的 `tool_allowlist` **默认为只读集**；加写权限需显式勾选 |
| **G3** | **`system_prompt` 拒绝控制字符** | 服务端 sanitize（防注入） |

**⚠️ G1 的必要性有实证**：EvoFlow 的原文警告——「用户明确要新建角色而你不按本 Skill **先盘点工具/技能再落盘，容易写出非法工具名或未启用技能**」。

### 4.3 岗位模板（6 类）

**字段结构**（每套模板）：

```
role_key / display_name
soul_md              气质、价值观、安全护栏        ← 偏「是谁」
system_prompt        步骤、输入输出、工具边界、何时拒绝 ← 偏「怎么做」
default_tool_allowlist / default_skills / default_autonomy_level
```

> **⭐ `SOUL` 与 `system_prompt` 的分工**（借 EvoFlow 的设计）：EvoFlow 把「**SOUL 偏『是谁』、`system_prompt` 偏『怎么做』**」分得很清。**现有表只有 `system_prompt`，建议补 `soul_md`**（字段已在 B1 规格 §3.3 建议中）。

**六类岗位的素材来源**（**许可状态已逐项核实**）：

| 岗位 | 素材来源 | 许可状态 |
| --- | --- | --- |
| **开发** | `anthropics/knowledge-work-plugins/engineering`（官方） | ✅ **Apache-2.0**（已读 LICENSE 原文） |
| **销售** | `anthropics/knowledge-work-plugins/sales`（36 个 skill，官方） | ✅ **Apache-2.0** |
| **管理** | `anthropics/knowledge-work-plugins/{data,operations,finance}` + `damiangao/agent-skills`（OKR） | ✅ **Apache-2.0** |
| **文案** | `coreyhaines31/marketingskills` + `LLL-178/cn-skills` + `199-biotechnologies/humanise-text-skill` | ✅ **均 MIT** |
| **策划** | `Weizhena/Deep-Research-skills` + `AgriciDaniel/claude-blog` | ✅ **均 MIT**（⚠️ claude-blog 的 `brain/` 子目录有许可冲突，**只引 `skills/`**） |
| **拍剪** | ❌ **无对口现成**（EvoFlow 有 25 个媒体 skill 但不可引；TabTin 只有 `cowart` 图片） | **必须自研** |

**⚠️ 三件事必须说清**：

1. **模板内容是"方法论"，不是代码**——写模板时要**自己写**（参考其 SKILL.md 的**方法**），**不是复制其文本**。理由：即使是 MIT/Apache，复制文本也会引入归属与维护负担；而方法论不受版权保护。
2. **拍剪岗必须自研**——这是 6 类里唯一没有现成可参照的。
3. **模板质量是本文最大风险**——见 §9.2 R1。

| # | 验收项 | 证据形式 |

| **A1** | 普通员工（非超管）能打开「我的数字员工」，**不再是 403** | 真机截图 + 接口响应码 |

| # | 风险 | 说明 | 缓解 |
