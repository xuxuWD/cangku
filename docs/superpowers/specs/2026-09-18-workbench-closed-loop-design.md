## 1. 一句话结论

我们的**骨架比 EvoFlow 硬**（闸门 / 隔离 / 审计 / 租户），但**工作台的体感部件几乎全缺**：没有"任务驾驶舱"、没有"员工值班"、没有"应用固化"、没有"资产中心"、没有"IM 触达"。v1 只诊断出 5 条接缝；v2 的对照表明：**要让这个东西真的像工作台，缺的不是 5 条接缝，而是 4 个产品部件 + 2 个入口通道。**

## 2. 闭环总图

### 2.1 四拍主循环（用户心智，借 EvoFlow「先选模式 → 看板观测 → 跑通沉淀 → 值班接管」）

```
   ① 选模式开工              ② 看板观测                ③ 跑通就沉淀              ④ 值班接管
┌────────────────┐   ┌────────────────┐   ┌────────────────┐   ┌────────────────┐
│ 对话四模式      │   │ 任务驾驶舱      │   │ 另存为应用      │   │ 排班心跳        │
│ 新建任务        │──▶│ 工作流 DAG      │──▶│ 资产中心        │──▶│ 待批 / 交工     │
│ 跑已有应用      │   │ 员工健康        │   │ 技能 / 资源包    │   │ 工作日志汇报    │
│ （＋新建对话）   │   │ 观测与排障      │   │ 记忆 / 经验      │   │ IM 推送回入口   │
└────────────────┘   └────────────────┘   └────────────────┘   └────────────────┘
        ▲                                                                  │
        └──────────────── 回 到 入 口（IM / 通知 / 待办 / 会话列表）────────┘
                    贯穿：授权闸门 · 审计 · 用量 · 权限 · 保留期
```

## 3. 五个必须闭合的接缝（S1–S6，本次 UI v2 内可完成）

| # | 接缝 | 现状断点 | 闭合要求（可检查） | 归属 |
| --- | --- | --- | --- | --- |
| **S1** | 审批「三处一致」 | 对话内联卡 / 运行详情 / 通知各自可达；通知无 conversation 目标类型 | 同一 `approval_id` 三处显示**同一权威态**；任一处决议后另两处刷新即一致；通知点开直达该会话的该条卡 | M1 + M3 |
| **S2** | 交付 → 验收 → 沉淀 | 有产物 chip 与结构判定端点，**无验收落点、无"存成应用/任务"入口** | 运行详情出**交付清单**（产物 + 结构判定 + 未达标项）；**确认完成 / 打回重做（带原因）**；确认后出现「**存成任务 / 设为自动化**」（B5 的轻量入口，完整画布见 C3） | M3 |
| **S3** | 通知/待办 → 回到会话/运行 | `InboxTargetType` 7 类，`openItem` **只处理 task/run**；运行详情无返回路径；全站无面包屑 | 7 类目标全部可点且落到正确页面；运行详情有面包屑 + 「回到会话」；**深链与浏览器后退不得破坏**（批1 G-01/02/03） | M2/M3 |
| **S4** | 干预闭环 | pause/resume/cancel **有端点无按钮** | 运行详情与右栏提供**暂停 / 恢复 / 取消**（二次确认 + 权威态回流）；**按钮隐藏 ≠ 权限** | M3 |
| **S5** | 待办与在岗可见 | 无「N 项待批」入口 | 首页指标卡「待我审批」与员工页横幅**同源**；点开直达审批（C 域立项前的**低成本替代**） | M1/M2 |
| **S6**（新） | **模式与场景可见** | `mode` 已在后端，前端只是一个下拉；无场景/工具画像、无斜杠指令 | 输入卡把**模式**做成一等公民（Ask/Plan/Goal 与自治档解耦的口径要有文案解释）；**斜杠指令最小集**（`/new /stop /help /status`）；**当前工具画像可见**（本会话能用哪些工具，A2 的替代实现） | M1 |

> **共同纪律**：一律走**服务端权威态**；不得用前端本地状态假装闭环；不得新增破坏既有深链的跳转方式。

## 7. 验收（闭环走查用例 v2）

**主流程（四拍走完）**：
① 工作台说一句话 → 会话（S6：模式可见）→ 出现审批卡（S1）→ 同意 →
② 右栏推进 + **任务驾驶舱里能看到它**（C2）→ 暂停一次再恢复（S4）→
③ 交工出产物 chip 与**交付清单**（S2）→ 打回重做一次 → 确认完成 → **存成任务/应用**（C3）→
④ 通知点开直达该会话（S3）→ 横幅/指标卡待办数一致（S5）→ 审计页可追全链路（⑩）。

**歪路（必走三种）**：① 审批**拒绝** → 过程如实记录"已跳过"，**不假装成功**；② 运行详情深链直开 → 面包屑正确、**返回不丢上下文**；③ 无权限身份点暂停/取消 → **服务端 403**（按钮隐藏不算数）。

**回归（不得破坏）**：深链与浏览器后退（G-01/02/03）· 四态齐备 · 会话上下文不丢 · 权威态回流 · 反假测试与一键全量。

**反假（新增三条）**：① 把 `pause` 改成纯前端置灰 ⇒ 必红；② 通知死胡同改成"点了没反应也算通过" ⇒ 必红；③ 把"待确认"与"已完成"合并成一个状态 ⇒ 状态语义用例必红。
