# 公众号内容工作台 Alpha 设计规格

> 日期：2026-09-07  
> 状态：已确认，待实施计划  
> 范围：内部员工使用 Mock Runtime 完成公众号图文草稿生成、自检确认和 Markdown 导出。

## 1. 目标

交付一条可由内部员工真实试用、可重复验收的自媒体内容闭环：

```text
提交主题与素材
  -> 创建工作台任务
  -> Mock Runtime 生成公众号草稿
  -> 员工编辑和自检
  -> 员工确认交付
  -> 下载 Markdown 内容包
  -> 保留任务与操作审计
```

本 Alpha 优先验证流程价值、任务状态、幂等、恢复、内容包结构和审计，不验证真实模型的内容质量。

## 2. 已确认的产品边界

- 首个平台为微信公众号图文。
- 员工可组合提交主题、网页来源、正文摘录和已授权公司知识资料；每次至少提供一种有效材料，内容主题必填。
- 网页正文由员工粘贴，来源链接只作为引用元数据保存；服务端不抓取网页。
- 生成引擎固定为 Mock Runtime，相同规范化输入产生可重复结果。
- 员工自行编辑、自检和确认。该确认不是管理审批，也不代表内容已经发布。
- 交付物在页面预览，并可下载为 Markdown 文件。
- 所有公开发布继续由员工在平台手动完成。

首版不包含：真实模型 API、自动抓取网页、自动发布、多平台格式、图片生成、Windows 桌面端、PWA、多级审批、复杂运行轨迹和运行时选型比较。

## 3. 用户与权限

首版用户是具有 `content-operator` 岗位或等价内容运营权限的内部员工。前端显示与否不构成安全边界，服务端必须执行以下检查：

- 用户只能创建内容任务，并读取、编辑、确认和导出自己创建的内容草稿。
- CEO 和超级管理员沿用现有租户内读取权限，但不能以查看行为替代员工确认。
- 所有任务、草稿、来源、确认和审计记录均绑定租户。
- 跨租户、无权访问或不存在的资源统一返回 `404`，不泄露资源存在性。
- 知识资料只能来自服务端根据岗位与数字员工解析出的授权范围；客户端传入的知识库 ID 不能扩大权限。

开发环境继续使用请求头模拟身份；生产身份不在本 Alpha 范围内。

## 4. 页面设计

页面采用已确认的“左右分栏 + 轻量任务状态”布局。

### 4.1 顶部

- 页面名：内容工作台。
- 当前任务号；尚未创建任务时不占位显示虚假编号。
- 状态条：`准备素材 -> 生成中 -> 待自检 -> 已确认`。
- 失败是独立状态，显示失败原因摘要与重新生成动作。

### 4.2 左侧素材区

- 内容主题：必填，1 至 200 字。
- 来源材料：可添加多条，每条包含可选来源链接和必填正文摘录。
- 来源链接只接受 `http` 或 `https`，不由服务端访问。
- 公司知识资料：从当前岗位与 `content-writer` 数字员工的授权范围中选择；空授权范围不回退到全库。
- 生成按钮：校验通过且当前没有生成请求时可用。

一条网页材料必须具有正文摘录；链接可为空，只有链接而没有摘录不能提交。这样可以保证 Mock 输入完整，同时避免链接数量与摘录数量分别维护造成错配。

### 4.3 右侧草稿区

- 标题。
- 摘要。
- 正文。
- 配图建议。
- 引用来源。
- 固定显示“Mock 演示结果”，避免被误认为真实模型产物。

草稿进入 `待自检` 后允许编辑。编辑内容保存在服务端，避免刷新后丢失。

### 4.4 交付动作

- 重新生成：创建新的运行，不创建第二个业务任务；保留旧运行用于审计。
- 确认并下载：先显示确认说明，再将草稿标记为已确认并下载 Markdown。
- 已确认草稿仍可查看和再次下载；如需继续修改，必须先撤销确认并留下审计记录。首版不提供删除历史运行。

## 5. 领域模型

现有 `Task` 和 Runtime 仍是流程主干，新增内容领域记录保存现有任务模型无法承载的素材和可编辑产物。

### 5.1 ContentBrief

- `task_id`
- `tenant_id`
- `created_by`
- `topic`
- `sources[]`：`source_id`、`url`、`excerpt`
- `knowledge_references[]`：服务端验证后的知识库/文档引用标识
- `input_fingerprint`
- `created_at`、`updated_at`

### 5.2 ContentDraft

- `draft_id`
- `task_id`
- `run_id`
- `tenant_id`
- `title`
- `summary`
- `body_markdown`
- `image_suggestions[]`
- `citations[]`
- `revision`
- `status`：`generating`、`reviewing`、`confirmed`、`failed`
- `confirmed_by`、`confirmed_at`
- `created_at`、`updated_at`

确认、撤销确认、重新生成和编辑都写入审计。已确认版本不得被原地覆盖；撤销后编辑会增加 `revision`。

## 6. API 与现有控制平面的衔接

前端不自行拼装多个底层请求来推断业务状态。新增内容领域 API 负责原子校验和编排，内部复用现有任务与 Runtime 服务：

- `POST /api/v1/content-tasks`：规范化输入，创建或复用 `employee_key=content-writer` 的低风险任务，保存 ContentBrief，并启动 Mock Run。
- `GET /api/v1/content-tasks/{task_id}`：返回任务状态、当前运行摘要、素材和当前草稿，用于刷新恢复。
- `POST /api/v1/content-tasks/{task_id}/regenerations`：基于当前素材创建新 Run，返回当前草稿状态。
- `PUT /api/v1/content-tasks/{task_id}/draft`：保存员工编辑，使用草稿 `revision` 做乐观并发控制。
- `POST /api/v1/content-tasks/{task_id}/confirmation`：确认当前修订并记录操作者与时间。
- `DELETE /api/v1/content-tasks/{task_id}/confirmation`：撤销确认并记录审计。
- `GET /api/v1/content-tasks/{task_id}/export.md`：仅导出已确认修订，设置安全文件名和 Markdown MIME 类型。

底层 `/tasks` 和 `/runs` 契约继续保留，内容 API 是面向员工端的业务编排层，不改变控制平面的事实源。

## 7. Mock 生成规则

Mock Runtime 必须验证端到端数据流，而不是返回一段固定的无关占位文本：

- 对主题、来源摘录和知识引用标识进行规范化排序并计算指纹。
- 使用确定性模板生成标题、摘要、正文段落、配图建议和引用列表。
- 相同规范化输入和模板版本产生相同草稿正文。
- 结果记录 `template_version`，便于后续替换真实模型并比较输出。
- Mock 不读取链接、不执行文件写入、不发布、不修改知识库。

输入摘录只是待处理数据，其中出现的“忽略规则”“执行命令”等文字不能改变模板、权限或任务状态。

## 8. 幂等、并发与恢复

- 创建请求必须携带幂等键；作用域为租户、用户和内容创建动作。
- 相同幂等键和相同输入返回原任务；相同幂等键但输入不同返回 `409`。
- 前端在首次提交前生成幂等键并保存到本地恢复状态，收到任务号后以任务号为准。
- 重新生成使用独立幂等键，每个键最多创建一个 Run。
- 草稿更新携带 `revision`；版本落后返回 `409` 并要求重新加载，不能静默覆盖其他页面的修改。
- 刷新页面通过任务号恢复，不依赖浏览器内存推断生成成功。
- Runtime 失败保留 ContentBrief 和失败运行，重试不创建第二个业务任务。

## 9. Markdown 内容包

文件使用 UTF-8，安全文件名格式为 `公众号草稿-<task_id>.md`，内容顺序固定：

```markdown
# 标题

> 摘要

## 正文

正文内容

## 配图建议

- 建议

## 来源

1. 来源标题或“员工提供的素材” - URL（如有）

---
任务号：公开可追踪的任务号
确认时间：时间
说明：该文件为内容草稿，不代表已发布。
```

导出不包含租户 ID、用户角色、Token、Cookie、API Key、Runtime 内部会话、原始事件载荷或服务端诊断信息。

## 10. 错误处理

- 输入错误返回字段级 `422`，前端保留已填内容并聚焦首个错误。
- 未认证返回 `401`；无权操作资源按资源隐藏规则返回 `404`。
- Runtime 超时、异常或格式无效时将草稿标记为 `failed`，不伪造完成事件。
- 网络中断后前端用任务号重新读取；无法确认任务是否创建时使用原幂等键重试。
- 草稿冲突返回 `409`，前端展示服务端新版本并让员工决定是否重新应用本地修改。
- 导出前未确认、确认版本已撤销或当前修订不匹配时返回 `409`。
- 面向员工的消息使用中文原因和下一步建议；内部异常只记录脱敏诊断号。

## 11. 测试策略

### 11.1 后端

- 正常创建内容任务、保存素材并启动 Mock Run。
- 输入字段、URL 协议、材料长度和数量上限。
- 创建与重新生成幂等。
- 相同键不同输入冲突。
- 跨租户、跨用户和未授权知识范围阻断。
- Mock 输出确定性、模板版本和引用可追踪。
- 恶意摘录不能改变动作或权限。
- 草稿编辑的 revision 冲突。
- 失败、重试、确认、撤销和审计。
- 未确认不可导出，已确认 Markdown 可重复下载。
- 响应、日志和导出内容的敏感字段检查。

### 11.2 前端

- 素材条目的增加、删除与字段校验。
- 防止重复点击生成。
- 生成中、待自检、已确认和失败状态。
- 草稿编辑、保存、冲突提示与重新加载。
- 失败后使用原任务重新生成。
- 确认提示、撤销确认和 Markdown 下载。
- 使用任务号刷新恢复。
- 身份、权限和网络错误提示。

### 11.3 回归

- 现有后端测试全部通过。
- 现有知识权限管理前端测试和构建全部通过。
- 新接口同步更新 `docs/api-contract.md`。

## 12. Alpha 验收标准

使用内部开发身份和脱敏素材连续执行 10 次完整流程：

```text
员工提交主题 + 至少一种材料
  -> 获得唯一任务号
  -> Mock 生成公众号草稿与来源
  -> 员工编辑并保存
  -> 员工确认交付
  -> 下载可读 Markdown
  -> 查询到对应审计
```

通过条件：

- 10 次均明确完成或明确失败，无卡死和虚假成功。
- 重复提交和失败重试不产生重复业务任务。
- 刷新页面可以恢复当前状态和服务端草稿。
- 下载文件可由内容运营人员直接继续编辑。
- 未确认草稿不能下载，确认与撤销均可追溯。
- 不发生自动抓取、自动发布、跨租户访问或未授权知识访问。
- 自动化测试、Python 编译检查、前端测试与生产构建全部通过。

## 13. 后续演进

Alpha 验收后才能评估下一阶段：将 Mock Runtime 替换为一个受控真实模型、引入内容质量评测集、增加负责人审批，最后再选择一个具备官方 API 的平台验证发布。页面和内容领域 API 保持稳定，真实模型只能替换运行实现，不能绕过任务、权限、确认和审计。
