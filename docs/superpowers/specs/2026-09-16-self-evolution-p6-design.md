## 1. 范围

### 1.1 什么是「自进化」（边界定义）

本立项交付的是**工程闸门**（立项 §15 #8 原文：「可交付的只有 P6 那套**工程闸门**；不得对外宣称『自主进化』」）：

```
成功运行轨迹 → 候选技能包（不生效） → held-out 严格提升评测 → 人工批准
             → 灰度（版本指针） → 观测 → 全量（人工） / 回滚（可自动，安全方向）
```

它不是「AI 自己改自己」、不是模型微调、不是无人值守自我改进。**对外口径收住**：只说「技能沉淀与版本治理」。

### 1.2 做什么（四件）

| # | 事项 | 一句话 | 主要依据 |
| --- | --- | --- | --- |
| A | **技能沉淀（候选生成）** | 从成功运行轨迹提炼技能包**候选**；候选只落 P4 `submitted`，无任何生效路径 | FlowEvo 范式（§14.1） |
| B | **评测集与准入闸门** | held-out 严格提升才接受；回归锁定用例**一票否决**；生成器不可见评测集 | SkillOpt 范式（§14.1） |
| C | **灰度与回滚（指针模型）** | 改**指针**不原地覆盖；观测期可自动回滚；第一版灰度范围 = `agent_key` 白名单 | Langfuse labels 范式（§14.1） |
| D | **效用追踪与负迁移抑制** | 技能调用结局信号 → 效用量 → 喂给回滚判据与运营指标 | §14.1「追踪每个技能的下游收益」 |

### 1.4 不做什么（明确排除）

1. **不引入 EvoFlow 代码**（PolyForm Noncommercial，只读学口径不变；`capability-ownership-map` #19/#28 红线）。
2. **不做无闸门自动晋升**（不采纳清单 #6：`consolidate_craft_overnight` 的 "No human approval" 与我方硬约束相反）。
3. **不做同模型家族自评**（不采纳 #4；实证 LLM 自评准确率仅 46.4%）；第一版**不引入 LLM-as-judge 作主判定**。
4. **不自动前进**：系统可自动**回滚 / 停用 / 收窄**（安全方向）；**永不允许**自动晋升、自动全量、自动启用新版本。
5. **不改 P4 状态机**：「灰度中/已全量/已回滚」是**指针表的属性**，不塞进 `submitted/approved/enabled/...`（唯一的语义变更点是展开路径指针化，见 §2.6，属专项评审）。
6. **不做技能市场 / 跨租户技能共享**（来源白名单语义不变）。
7. **不接外部评测平台**（M4「评测集长在我们这里」不可外包）。
8. **不自动改写「人格/规则类记忆」**（§6.2：写入强制人工在环；本层对记忆只读）。
9. 不做「把先问用户写进提示词当确认机制」（不采纳 #12）。
10. **不复制内容安全评估套件的结论**：既有套件是抽样断言非证明（其 §5 结论边界照旧）。

## 2. 设计

### 2.1 三层分工（沿用 §14.1 决议，不重开）

| 层 | 采用 | 职责 | 我方落地方式 |
| --- | --- | --- | --- |
| 技能沉淀 | FlowEvo 范式 | 成功运行 → 编译成技能 → 持久技能库 → 效用追踪 → 抑制负迁移 | 候选生成器（§2.2）+ 效用表（§2.4） |
| 准入闸门 | SkillOpt 范式 | `rollout → reflect → 受限编辑（编辑预算）→ held-out 严格提升才接受 → 导出` | 评测运行器（§2.3）+ P4 人工审批（§2.5） |
| 灰度回滚 | Langfuse labels 范式 | 版本 → 校验 → 门禁 → 灰度 → 观测 → 回滚（**改指针，不原地覆盖**） | 指针表（§2.4） |

**接缝（我方独有，两个开源件都不提供）**：admission 环节插入 P4 既有**人工审批**——「数字员工想固化一条新技能时，人审一次」；**生成者 ≠ 评审者**为硬约束（§2.5）。

### 2.2 事项 A：技能沉淀（候选生成）

- **输入**：真实运行轨迹 = 对话会话 + 工具执行记录（九步闸门审计）+ 审批结论/驳回原因 + M3 技能经验记忆（`[skill:key@version]` 事实记忆）。**只读**，不写任何生产配置。
- **输出**：技能包**候选**（正文草案 + `allowed-tools` 子集 + 证据引用 `run_id` 列表）。
- **约束（fail-closed）**：
  1. 候选必须携带 ≥ 1 条真实运行证据（`run_id` + 可判定结局），否则**拒绝生成**；
  2. 候选**只能落入 P4 的 `submitted`**（走 `POST /api/v1/skills` 同一校验链：validator / 许可白名单 / `allowed-tools` 逐键 / D11 描述扫描 / 64 KiB 体积上限 / `content_sha256`）；
  3. `source_key='evolution'` 必须 ∈ 部署注入白名单（空白名单 = 技能层关闭，沿用 P4 §2.3）；
  4. **受限编辑（编辑预算）**：候选正文 ≤ 既有上限；`allowed-tools` 必须 ⊆ 来源运行实际用过的工具 ∩ `ToolSpecCatalog`；候选**不得**触碰评测集、工具目录、权限判定、状态机。
- **owner 语义（待裁决点 C/D 的交叉项）**：候选 owner 记为**系统标识 `system:evolution`**（非自然人）——否则单管理员部署下「提交人不得自审」会锁死审核链。这需要对 P4 做一处小扩展（允许系统标识作 owner），属专项评审。

### 2.3 事项 B：评测集与准入闸门

**用例来源（优先级从高到低，D13 口径落地）**：

| 来源 | 说明 |
| --- | --- |
| ① 真实运行轨迹回放 | 从可判定结局的运行提炼：输入（脱敏快照）+ 期望（程序断言） |
| ② 人工专家编写 | `super_admin`/业务专家按模板写用例（含反例与边界） |
| ③ 回归锁定（永不回退基线） | 接入既有安全/探针套件（`content_safety_evaluation.py` 模式、跨租户探针、`app/runtime/evaluation.py` 的最小断言），作为**只增不减**的回退基线 |

> **采集器 v1 实现口径（2026-09-16 如实登记）**：数据源 = 审计中**被拦截**的受控动作（`tool.blocked` / `knowledge.search.blocked`），产出 **草稿**用例（`source=run_trace`，**期望留空、由专家补全后才能发布**）。**不自动提炼可回放期望**的原因：系统按设计不落原文（工具参数只存摘要、知识检索 query 不记、审计明细为白名单受控值），在无原文前提下「自动提炼」必然造假 ⇒ **宁缺勿造**。**幂等**：同一条记录重复采集按快照指纹去重，不产生第二条用例。

**held-out 的物理含义 = 生成器不可见**：候选生成路径**不得访问**评测集表——代码级隔离（P6b 落地时：`app/evolution/` 内候选生成模块不 import 评测仓储；启动期断言该隔离成立）。

**准入门槛（fail-closed，逐条）**：

1. **严格提升**：候选主指标（程序判定的任务成功率）**严格 >** 基线版本，且 `suite_digest`（用例集指纹）与基线一致——**不同题面不得比较**；
2. **一票否决**：任一 P0/P1 用例回退，或任一「回归锁定」用例失败 ⇒ 拒绝；
3. **样本量与稳定性**：每候选 ≥ `WORKBENCH_EVOLUTION_EVAL_MIN_RUNS`（默认 3）次评测；确定性断言单次判定；不稳定用例以**最差一次**计入（不取平均掩盖回退）；
4. **成本上限**：单次评测运行费用上限（配置）——超限 fail-closed 中止并留痕；评测运行全部走 `usage_ledger` 计费（对齐 §15 #4 成本熔断）；
5. **评分器纪律**：主指标只接受程序断言；主观质量维度只作**人工参考**，不进「严格提升」判定。

**评测集治理（防「改考题过审」）**：

- 用例状态机 `draft → published → archived`（any → archived；**不物理删**；变更走 supersede，对齐知识治理口径）；
- 每次评测运行记录**用例集指纹 `suite_digest`**（对 published 集合派生）——事后可验证「当次到底考了什么」；
- 用例增删改必须审计；**评测集变更与候选放行不得由同一次动作合并**；
- **存放**：库内表（多租户 + 版本化 + 权限）；仓库内保留「回归锁定用例」的代码级实现；用例内容必须脱敏（不得含密钥 / 他人个人信息 / 跨租户数据）。

### 2.4 事项 C：灰度与回滚（指针模型）【待裁决点 B】

**指针表草案**（`workbench_skill_pointers`）：

```sql
CREATE TABLE IF NOT EXISTS workbench_skill_pointers (
    tenant_id         TEXT NOT NULL,
    skill_key         TEXT NOT NULL,
    active_version    TEXT NOT NULL,           -- 全量生效版本
    canary_version    TEXT,                    -- 灰度版本（NULL = 无灰度）
    canary_scope      JSONB,                   -- 第一版 {"agent_keys": [...]}（确定性白名单）
    canary_started_at TIMESTAMPTZ,
    updated_by        TEXT NOT NULL,
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (tenant_id, skill_key),
    FOREIGN KEY (tenant_id, skill_key, active_version)
        REFERENCES workbench_skills(tenant_id, skill_key, version),
    FOREIGN KEY (tenant_id, skill_key, canary_version)
        REFERENCES workbench_skills(tenant_id, skill_key, version)
);
```

> 复合外键 ⇒ 跨租户引用在 **DB 层直接失败**（沿用 023/030 手法）；`canary_version` 为 NULL 时该外键不检查（PG 默认语义，符合预期）。

**展开规则（对 P4 §2.4 的语义收窄 · 专项评审点）**：`expanded_tools_for_agent` 由「所有 enabled 版本并集」改为**按指针解析的单一版本**：

- `agent_key ∈ canary_scope.agent_keys` ⇒ 取 `canary_version`；**fail-closed**：canary 版本不可用则拒绝展开该 key，**不回退** `active_version`；
- 否则取 `active_version`；
- **无指针行 ⇒ 该 `skill_key` 不展开**（fail-closed：「enabled 但未被指针指向」= 候选/待灰度，不进生产工具面）；
- 迁移影响：P4 **零默认技能**（生产当前是否已启用技能：**待核实**）⇒ 切换成本低；P4 用例同步清单见 §2.6。

**灰度范围第一版**：仅 **`agent_key` 白名单**（确定性、可审计、回滚语义清晰）；**不做比例分流**（需会话级哈希路由，行为不确定、审计难解释）。

**观测信号与自动回滚**（阈值建议值待裁决）：

| 触发 | 建议阈值 | 动作 |
| --- | --- | --- |
| 技能调用失败率超阈 | ≥ 50% 且样本 ≥ 5 | 自动回滚指针 → `active_version` + 审计 + 通知 |
| 连续失败 | ≥ 3 次 | 同上 |
| 守卫拦截（越权尝试） | **0 容忍** | 同上 |
| 定时评测重跑退化 | 「回归锁定」用例失败 | 同上 |

**红线**：自动只允许**向安全方向**（回滚/停用）；**恢复全量必须人工**。

**审计**：每次指针变更（启动灰度 / 全量 / 回滚 / 人工改指）写 append-only 审计；明细优先复用现有键（`skill_key`/`version`/`agent_key`/`reason`/`status`/`run_id`），确需新增（候选：`from_version`/`to_version`/`trigger`/`suite_digest`/`eval_run_id`）逐键评审加入，白名单零默认放开。

### 3.1 正常流程（**查库验证**，不只看接口 200）

1. 生成候选 → `workbench_skills` 出现 `status='submitted'` 行，`source_key='evolution'`，owner=`system:evolution`，`content_sha256` 非空；**展开路径不变**（未批准，工具面无变化——查库 + 工具面双重断言）。

## 6. 风险与红线

1. **「自进化」对外收住**（§15 #8）：可交付的是工程闸门；**不得**对外宣称「自主进化 / 无人值守自我改进」。
2. **生成者 ≠ 评审者**（硬约束）：生成器不可见评测集（物理隔离）＋ 候选审批必须人工；**禁止**同模型家族自评。
3. **自动只向安全方向**：自动回滚/停用允许；**自动晋升/自动全量一律禁止**（本立项的最高红线）。
4. **成本失控**（§15 #4）：评测运行计费 + 单次上限 + 三级熔断；超限 fail-closed，不静默降级。
5. **技能包投毒**（§15 #3）：候选与人工提交**同强度**校验（来源白名单 / 许可 / 工具键交集 / D11 扫描 / 体积上限 / 指纹）；候选不因为「机器生成」而获得任何捷径。
6. **评测试题被污染**：`suite_digest` 留痕 + 用例变更审计 + 变更与放行分离；用例内容脱敏。
7. **许可纪律**：不引入 EvoFlow 代码（PolyForm Noncommercial）；不引入 DeerFlow/OpenViking 实现。
8. **零默认行为**：P6 未开启 = 与今天完全一致；首批数据表在 P6a 只增不改既有表（指针表在 P6b 启用，启用时按 §2.6 同步 P4 用例）。
