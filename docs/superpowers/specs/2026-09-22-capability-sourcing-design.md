## 3. ⭐ 关键区分：`SKILL.md`（指令）vs `scripts/`（代码）

**本文提出的区分，是整个方案的支点**：

| 形态 | 本质 | 应走的口径 |
| --- | --- | --- |
| **`SKILL.md` 正文** | **自然语言指令**——它是**方法论**，是"怎么做事"的描述 | ✅ **"只读研读"**（与 `architecture.md` 模式③同款）——**方法论不受版权保护**，读它、自己写 |
| **`scripts/` 目录** | **可执行代码** | ⚠️ 这才是"搬代码"，须许可 + 准入门槛 |

**为什么这个区分成立**：

- 一个 skill 的价值**主要在它的 SKILL.md**——它教你"怎么写公众号选题""怎么去 AI 味""怎么做竞品拆解"
- **而这些方法，你自己写一遍，效果一样，且零供应链风险**
- 反过来，skill 里的 `scripts/` 往往是**辅助工具**（格式化、调用 API），**不是核心价值**

**⇒ 由此得出建议方案。**

## 4. 建议方案：三层分类处置

| 层 | 来源 | 处置 | 本期 |
| --- | --- | --- | --- |
| **L0 方法论** | 外部 skill 的 `SKILL.md` **正文** | ✅ **只读研读 ⇒ 自己写**（**不复制文本**） | ✅ **可做** |
| **L1 方法 + 脚本** | 有 `scripts/` 的 skill | ⚠️ 脚本按"搬代码"口径：**许可 + 7 步准入链** | ⏸ 本期**不做**，留 M2 |
| **L2 自研** | 全网没有的 | ✅ **自研** | ✅ 可做（见 §6） |

### 4.1 为什么建议 L0 本期做、L1 留后

| 理由 | 说明 |
| --- | --- |
| **拿到的是能力，不是代码** | 用户真正要的是"策划的数字员工会做选题"，不是"装上别人的选题脚本" |
| **零供应链风险** | 不引入外部代码 ⇒ P4 的"技能包投毒"攻击面**不扩大** |
| **零许可负担** | 方法论不受版权保护 ⇒ 不需要逐个核对 LICENSE、不需要归属声明、不需要跟踪上游更新 |
| **与用户既有口径一致** | **对 TabTin / EvoFlow 用的就是"只读研读、自研"**（`architecture.md` 模式③）——**对 skill 用同一个口径，不引入第二套规则** |
| **P4 不需要变更** | L0 走的不是"技能包引进"通道，**是人工写 SKILL.md**——**P4 的六项能力完全覆盖**（注册表 + 审核 + 白名单 + hash + 沙箱） |

**⚠️ 一句话**：**L0 让本轮需求可以在不改任何已评审规格的前提下被满足。**

### 4.2 L1 若将来要做：7 步准入链（设计留档，本期不实施）

```
① 回源核实      聚合站条目必须定位到原始 GitHub 仓库（本轮发现：多个条目只在聚合站可见、定位不到源仓库）
② 许可核实      读 LICENSE 原文；无 LICENSE = 拒绝
                ⚠️ 补充检查点（本轮实证）：
                  · 子目录是否有独立 LICENSE（claude-blog/brain/ 与根 MIT 冲突）
                  · 内嵌第三方素材（vtake-skills 的 GSAP 有"终端用户不得付费"条款）
                  · 根 MIT 不重新授权第三方素材（LeadMagic/LICENSE-NOTES 自述）
③ 静态扫描      Snyk `mcp-scan --skills` / ATR 规则集（113 条，映射 OWASP Agentic Top 10）
④ SKILL.md 审查 提示注入 / 隐藏 Unicode Tag 字符（U+E0000–U+E007F）/ 远程获取指令
⑤ 脚本审查      所有 scripts/ 逐行看
⑥ 沙箱试跑      隔离环境（--network none / 只读 / 非 root）
⑦ 白名单准入    锁定 hash，变更告警
```

**⚠️ 与 P4 的四层关系**：P4 有「来源白名单 + 人工审核 + hash 复核 + 沙箱只读」。7 步准入链**前三步是新增的**（回源 / 许可 / 静态扫描）——**即 P4 假设"来源是受控的"，而 7 步假设"来源是不可信的"。这是两种威胁模型。**
