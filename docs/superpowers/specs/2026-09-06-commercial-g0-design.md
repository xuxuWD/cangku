# 私有部署与内部版商业化 G0 设计规格

> 日期：2026-09-06  
> 状态：待用户审阅  
> 适用范围：公司内部版、客户私有部署版；SaaS 托管版作为后续扩展，不在本阶段实现。

## 1. 目标

把现有控制平面从“内部技术 POC”推进为可交付的私有部署/内部版基础产品，同时为后续 SaaS 复用同一套领域模型和 `/api/v1` 契约。

本阶段不追求一次完成所有岗位和所有外部平台，而是建立客户可以部署、管理员可以管理、用量可以核算、数据可以导出/删除、版本可以升级/回滚的商业化内核。

## 2. 非目标

- 不在本阶段实现公有云 SaaS 多租户托管、在线支付和自动开票。
- 不把 DeerFlow、Codex、Hermes 源码复制进工作台主仓库。
- 不实现 Cookie 嗅探、私有接口模拟、验证码绕过、风控规避或设备伪装。
- 不同时交付全部岗位的完整自动化；首个业务闭环仍是自媒体运营 + CEO/GEO 看板。
- 不允许 Agent、Runtime 或客户端成为权限、账单或任务最终状态的事实源。

## 3. 产品形态

### 3.1 内部版

- 部署在公司服务器或公司云账号。
- 初始只服务本公司一个主租户，但数据模型保留租户字段，禁止写死单租户逻辑。
- Windows 桌面端供员工使用，网页管理台供超级管理员和 CEO 使用，PWA 供审批和紧急处置使用。
- 内部版不向员工展示计费页面，但后台必须记录模型和 Runtime 用量。

### 3.2 私有部署版

- 每个客户独立部署一套控制平面、数据库、缓存、对象存储和 Worker。
- 客户管理员负责本租户员工、岗位、知识库和设备管理。
- 供应商运维只能通过客户授权的诊断入口查看脱敏指标，默认不能读取客户原文。
- 安装、迁移、升级、备份、恢复和回滚都必须有版本号和操作记录。

### 3.3 SaaS 预留

- 所有核心对象保留 `tenant_id`、`workspace_id` 和审计字段。
- API、事件、用量账本和权限接口不依赖本地文件路径或单机状态。
- 将来 SaaS 只替换部署拓扑、客户开通、计费和托管运维，不重写任务、知识库和 Runtime 契约。

## 4. 核心领域模型

### 4.1 租户与工作区

`Tenant` 表示公司或客户边界，`Workspace` 表示租户内的业务空间。所有用户、岗位、数字员工、知识库、任务、运行、产物、用量和审计记录必须归属于租户；项目级资源同时带工作区或项目标识。

租户状态：`trial`、`active`、`suspended`、`exporting`、`deleting`、`deleted`。

私有部署版默认只有一个客户租户，但必须通过相同租户校验路径，不能因为“单租户部署”跳过权限检查。

### 4.2 客户管理员与岗位

保留 CEO 与超级管理员分离：

- 超级管理员：系统安全、模型、Runtime、岗位、知识范围、设备和技术配置。
- CEO：经营看板、业务审批、预算审批和紧急暂停。
- 客户管理员：只管理本租户员工、岗位、设备和业务配置，不能查看供应商其他租户。
- 普通员工：只能使用被授予的岗位和数字员工。

岗位能力包包含入口、默认 Agent、技能、提示词版本、模型范围、知识范围、动作白名单、审批规则和评测集。

## 5. 套餐与用量账本

### 5.1 套餐

首期只定义三种产品档位，不接在线支付：

| 档位 | 使用场景 | 限制方式 |
|---|---|---|
| 内部版 | 公司自用 | 记录用量，不向员工计费 |
| 专业私有部署版 | 中小客户试点 | 席位、任务运行量、存储和模型预算 |
| 企业私有部署版 | 多部门客户 | 更高并发、专属模型/Runtime、审计和维护服务 |

套餐配置必须版本化，已生效账期不能被直接覆盖；调整通过新版本和生效时间完成。

### 5.2 用量账本

`UsageLedgerEntry` 只追加，不允许原地修改。每条记录至少包含：

- 租户、工作区、用户、岗位、数字员工；
- 任务号、运行号、步骤号；
- Runtime、模型、模型版本；
- Token、图片、视频、语音或其他媒体用量；
- 估算成本、币种、发生时间；
- 成功/失败、失败原因、是否计入额度；
- 幂等键和来源事件号。

重复事件不得产生重复账本。账单纠正必须新增冲正记录，并引用原账本号。

### 5.3 超额策略

每个租户可以配置：`阻断`、`仅允许低成本模型`、`转人工审批` 三种策略。默认策略为阻断高成本动作并通知管理员。

客户端不能提交自己的预算或计费结果；服务端根据租户套餐、岗位预算和任务快照计算。

## 6. 数据生命周期

### 6.1 导出

客户管理员可以申请导出本租户的：

- 用户、岗位、数字员工配置；
- 任务、运行、步骤、产物元数据；
- 知识文档元数据、版本和引用关系；
- 记忆、成长提案和审核记录；
- 用量账本和审计记录。

导出任务异步执行，生成带过期时间的下载包。默认不导出密码、Token、Cookie、原始 API Key、浏览器会话或供应商内部密钥。

### 6.2 删除

租户删除采用两步流程：管理员申请 → 冷静期 → 执行删除。删除前必须生成最终导出包并记录确认人。业务数据、对象存储文件、向量索引和缓存按策略清理；审计记录保留最小必要元数据，标记租户已删除，不保留客户原文。

### 6.3 保留

默认保留策略：任务和运行 180 天、事件和用量 365 天、审计 730 天。客户可以缩短期限，延长期限需要明确配置和存储评估。任何保留策略变化都写入审计。

## 7. 部署、升级和回滚

私有部署交付包必须包含：

- 控制平面镜像或 Python 发行包；
- 桌面端安装包和版本清单；
- 数据库迁移脚本；
- 配置模板和密钥注入说明；
- 备份、恢复、健康检查和回滚脚本；
- 客户管理员手册、员工手册和故障手册。

升级流程：备份 → 预检查 → 数据库迁移 → 服务滚动更新 → 冒烟测试 → 观察 → 完成。迁移失败必须停止发布并恢复上一版本；禁止直接删除旧字段或覆盖客户数据。

版本至少包含控制平面版本、数据库迁移版本、桌面端版本、Runtime 版本和岗位能力包版本。

## 8. 安全与威胁模型

### 8.1 主要威胁

- 客户租户越权读取其他租户数据；
- Agent 或 Runtime 借助 Prompt 注入扩大工具权限；
- 外部 Runtime 泄露客户知识、文件或模型凭据；
- 用量账本被重复记账或被客户端伪造；
- 私有部署升级破坏数据或无法回滚；
- 管理员误把高风险能力授予普通岗位；
- 日志、备份或导出包泄露敏感信息。

### 8.2 防护要求

- 权限由服务端策略中心强制执行，前端隐藏按钮不算安全措施。
- 每次工具调用重新校验租户、用户、岗位、项目、设备、文件范围、预算、风险和授权有效期。
- 外部 Runtime 只获得短期授权和脱敏上下文，不直连 PostgreSQL、Redis、GEO 或对象存储。
- 计划阶段不得执行写入、发布、删除、权限变更或生产工作流修改。
- 所有高风险能力默认审批、灰度、观察和可回滚。
- 日志、事件、备份和导出包执行敏感字段脱敏。
- 供应商诊断默认只读指标，不读取客户原文。

## 9. 开源组件策略

- DeerFlow：作为可选长任务 Worker，固定版本、独立部署、MIT 和依赖审查通过后使用。
- Codex：作为 FDE Worker，Apache-2.0、独立沙箱和白名单工具；不作为普通员工万能 Agent。
- Hermes：作为成长/记忆提案 Worker 或能力参考；所有结果必须进入待审核状态。
- EvoFlow：非商业许可，不进入商业发行包。
- 任何组件进入客户交付包前，必须登记目标 commit、许可证、NOTICE、依赖 SBOM、漏洞扫描、商标声明和退出方案。

## 10. G0 验收标准

G0 完成必须有自动化测试和操作记录证明：

1. 两个租户的用户、岗位、任务、知识范围、运行和审计完全隔离。
2. 客户管理员无法查看供应商租户或其他客户租户。
3. 用量账本按任务和运行幂等记账，冲正不修改原记录。
4. 超出套餐额度时按租户策略阻断、降级或进入审批。
5. 客户管理员可以申请并下载脱敏导出包。
6. 租户删除流程包含冷静期、确认、清理和审计记录。
7. 备份恢复后租户、任务、账本和审计关系保持一致。
8. 升级失败可以回滚到上一版本，且不丢失客户数据。
9. 供应商诊断和外部 Runtime 不会读取客户原文或原始密钥。
10. 内部版和私有部署版使用同一套 API 契约，未引入单租户特例分支。

## 11. 后续实施顺序

1. 租户、工作区、客户管理员和资源归属模型。
2. 套餐配置、用量账本、额度检查和冲正机制。
3. 导出、删除、保留策略和审计。
4. 备份、恢复、升级和回滚工具。
5. 真实内部版闭环：自媒体运营 + CEO/GEO 看板。
6. 一个真实客户私有部署 Pilot。
7. Pilot 通过后再设计 SaaS 托管、在线支付和自动开通。

## 12. 明确的商业承诺边界

在 G0、内部 Alpha 和客户 Pilot 全部通过前，对外只能说：

> “提供可私有部署的企业数字员工工作台试点方案，支持岗位权限、企业知识库、受控 Agent 任务和人工审批。”

不能说：

- 所有岗位都能无人值守完成工作；
- 所有平台都支持自动发布；
- Agent 拥有无限权限；
- 已经支持成熟 SaaS 计费和大规模多租户；
- 已经完成所有模型、Runtime 和真实平台的生产验收。
