### 1.4 开工条件（V2 输入清单）

1. **外部输入**：I1–I14 全部到位——重点 I3 / I4（独立 PG + pgvector）、I5（只读账号）、I10（超管）、**I12（专用探针账号，会被短时锁定，禁真人账号）**、I13（死信渠道，第 2 类接口 5/6 的记录面可暂缺）。
2. **写授权**：复测含造数（任务 / 提案 / pending 账号）与账号锁定（第 8 类），须**单独授权**（runbook §5 口径，与 1.6 / 1.8 同类）。
3. **账号矩阵**：超管 × 1；employee × 2（**同租户不同人**——供第 1 类「同租户非发起人」与第 2 类）；**第二租户**（由超管走注册 + 审批自建）；专用探针账号 × 1（I12）；各员工须**已完成 TOTP 绑定**（否则仅得受限会话 `scope=totp_enrollment`，无法复现 403 面）。
4. **演练租户约定**（待裁决 A3）：造数一律落在演练租户，执行后按手册 §11 清理。

### 1.5 不做什么（明确排除）

1. **不在生产复测**；不触碰 staging 之外任何环境；**AI 不连 staging**（由用户在服务器执行、回传脱敏输出后判读）。
2. **不扩面**：八类之外不新增检查（如 TLS/HSTS、网关限流、WAF、外部平台——报告 §5 其余行属另一立项）；复测中发现的新问题**只登记、不现场修**。
3. **不新增 / 不修改脚本**：V1 零代码；V2 若确需脚本化，另立专项评审（含六要素回填），**不在本期夹带**。
4. **不为让复测通过改任何配置**（如临时 `WORKBENCH_ENV=development`、放宽限流、清空白名单）——期望不符即如实登记为差异（§2.4）。
5. **不复测开发态约定**：报告第 6 类 development 态请求头身份 `200` 是设计内约定（报告 §4 已知限制 8），staging 只复测其反面（`401`）。
6. **敏感值红线**：口令 / 令牌 / DSN / 密钥不入对话、不入文档、不入证据（`***`）；`AUTH_SECRET` 字面比对由**部署侧**执行，只回「命中 / 未命中」，密钥值不回传。

## 2. 设计

### 2.1 证据口径（每项检查留档三件）

1. **请求**：方法 + 路径 + 身份（哪类账号）+ 载荷特征（注入串 / 多余字段 / 伪造头）；
2. **响应**：状态码 + **脱敏后**的响应摘要；
3. **判读**：期望 / 实际 / 结论（通过 / 差异 / 未复测）。

约束：令牌与口令**不入证据**；响应摘要不得包含明文手机号、口令 / 哈希、密钥、令牌值；回传前一律 `***` 替换。

### 2.2 复用资产映射（不新写代码的前提）

| 复用资产 | 覆盖 | 调用口径 |
| --- | --- | --- |
| `scripts/cross_tenant_probe.py` | 第 1 类（6 类 KIND） | 参数 `:309-320`；每 KIND 一行 `--resource "KIND:A_ID:B_ID"`；缺 `--resource` ⇒ `exit=2`（`:335-337`） |
| `scripts/staging_concurrency_probe.py` | 第 8 类（登录限流并发） | `--scene login_throttle`；**第一次 `{401:8}` 属已知并发窗口、紧接第二次 `{429:8}` 才算通过——不得因此改代码 / 改配置**（口径同 1.8 子项 `:52-53`） |
| `scripts/customer_acceptance_probe.py` | 第 7 类（脱敏 / 审计面） | `_check_audit_log:521`（参数 `:659-683`） |
| **手册请求清单**（curl 直达） | 第 2–6 类 + 第 3/7/8 类补充 | 由报告 §2 的本机 `TestClient` 用例**逐条转写**；不新写脚本 |

### 2.3 不可造场景与替代口径（**待裁决 A1**）

| 场景 | 为什么不可造 | 替代口径 | 结论口径 |
| --- | --- | --- | --- |
| 已过期令牌（第 3 类） | 令牌由服务端签发，staging 无法人工制造过期令牌（等自然过期不现实） | **登出撤销后复用同令牌**（`POST /api/v1/auth/logout` → 旧令牌再请求 → 期望 `401`） | 如实标注「过期路径未复测（本机已覆盖）」 |
| 生成器伪造 `kind`（第 4 类局部） | 需**可控生成器**（本机注入 fake planner）；staging 为真实生成链路 | 观察式复测：响应步骤 `kind` / `requires_approval` 由服务端产出（与工具白名单一致） | 如实标注「生成器伪造面未复测（本机已覆盖）」 |
| development 态 `X-User-*` `200`（第 6 类） | 设计内约定，staging 必须关闭 | **不复测**（只复测其反面 `401`） | 不计入差异 |

### 2.4 停手规则（宪法 §七）

任一类与期望不符 ⇒ **停手** → 报错原文一字不改登记 → 沿调用链定位第一可观测异常点 → **不得调配置 / 改代码使其通过**；是否修复另行立项 / 变更，不在本期现场处理。

1. **写操作未授权不得执行**；V2 全程限定在演练租户 + 专用账号（I12）内。

5. **AI 不连 staging / 生产**（宪法 §六）：复测由用户在服务器执行、回传脱敏输出。
