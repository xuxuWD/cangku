# Agent 执行内核 POC 设计规格

> 日期：2026-09-06  
> 状态：待评审  
> 范围：开源 Harness 隔离试点，不改变公司工作台控制平面事实源。

## 1. 目标

验证开源 Harness 是否能承担公司工作台的 Agent 执行层，同时保持公司自己的租户、岗位、权限、预算、审批、审计、知识库和 GEO 边界不变。

本 POC 只验证真实业务价值和适配成本，不承诺任何 Harness 进入生产，也不把第三方仓库复制进主仓库。

## 2. 岗位范围

首批采用一个合并岗位：**AI 产品与交付工程师岗**。

该岗位包含两个受权限控制的工作模式：

### AI 产品经理模式

- 需求访谈整理、PRD、用户故事、流程说明和验收标准；
- 竞品调研、功能对比、用户反馈归纳和需求优先级；
- GEO、内容、销售和管理岗位之间的需求协调；
- 只允许生成方案、草稿和任务计划，不直接修改生产系统。

### FDE 交付工程师模式

- 客户环境和业务流程梳理；
- 工作台部署、模型/知识库/连接器配置；
- 项目范围内的问题排查、试点支持和验收报告；
- 使用受限本地文件、代码沙箱和白名单工具完成交付动作。

两个模式共享岗位身份，但拥有不同的动作策略、知识范围、文件范围和审批要求。FDE 不因此获得超级管理员权限。

## 3. 试点候选

### 3.1 DeerFlow 2.0：通用长任务候选

- MIT 许可证，Python 生态；
- 重点验证计划、子 Agent、长任务、记忆、技能、沙箱、任务恢复和研究/内容工作流；
- 作为独立外部运行时启动，固定版本和依赖；
- 不接管公司用户、权限、预算或任务最终状态。

### 3.2 Codex Harness / App Server：受控执行候选

- Apache-2.0，Rust 生态；
- 重点验证 FDE 的文件操作、审批请求、流式事件、任务中断、沙箱和失败恢复；
- 通过 App Server/SDK 适配器接入，不把 Rust 内核直接嵌入 FastAPI 进程；
- 首期不把它作为自媒体、销售或知识库 Agent 的唯一运行时。

### 3.3 Hermes Agent：成长能力参考

- MIT 许可证，Python 生态；
- 只验证记忆整理、技能候选和跨会话经验提炼；
- 任何自动生成的技能、提示词或记忆只能进入待审核提案，不能直接写生产配置。

### 3.4 DeepSeek Harness：实验对照

- MIT 许可证，TypeScript 生态；
- 用于观察插件化、多 Agent 和模型路由设计；
- 因开发预览版和破坏性变更风险，不作为首期生产候选。

## 4. 统一适配器契约

公司工作台定义 `AgentRuntimeAdapter`，所有外部 Harness 只实现此接口：

```text
start_run(context, plan) -> run_id
stream_events(run_id, cursor) -> events
pause_run(run_id, reason)
resume_run(run_id)
cancel_run(run_id, reason)
request_approval(run_id, action) -> approval_request
get_checkpoint(run_id) -> checkpoint
replay_run(run_id, from_step)
get_usage(run_id) -> model/tool/cost/latency summary
health() -> runtime version/capabilities/sandbox status
```

`context` 至少包含租户、用户、岗位、工作模式、项目、任务号、设备、知识范围、文件范围、预算、风险等级、授权有效期和策略版本。

外部 Harness 的 thread、session、checkpoint、内部日志和子任务号只作为实现字段保存，不能覆盖工作台任务状态、审批结论或权限判断。

## 5. 任务执行流程

```text
员工提出目标
  → 工作台创建任务并生成风险/预算/权限快照
  → Agent Runtime 生成计划和依赖图
  → 工作台检查计划、动作和知识范围
  → 低风险步骤自动执行
  → 高风险动作请求工作台审批
  → Runtime 流式回传步骤、工具、产物和错误事件
  → 工作台验收成功条件、记录证据并更新最终状态
```

计划阶段不得执行写文件、发送消息、公开发布、删除、权限变更、生产工作流变更或其他不可逆动作。

## 6. 试点业务用例

### 用例 A：AI 产品经理模式

输入：一段客户需求和已有产品资料。  
预期：生成需求摘要、问题清单、PRD 草稿、验收标准和待确认项，并引用知识来源。  
禁止：写入生产知识库、修改工作流、对外发送或替用户承诺交付时间。

### 用例 B：FDE 模式

输入：一个经过授权的 staging 项目和部署任务。  
预期：读取授权目录、运行白名单检查、生成配置建议、执行沙箱内验证并输出验收报告。  
禁止：访问授权目录之外的文件、读取密码/Cookie/验证码/API Key、修改生产数据库或绕过登录/风控。

### 用例 C：失败恢复

模拟模型超时、工具失败、网络断开、审批等待和进程重启，验证任务可暂停、继续、有限重试、回放并保持幂等。

## 7. 安全边界

- Harness 进程不直接连接 PostgreSQL、Redis、GEO 数据库或对象存储；统一通过工作台 API/受限工具网关访问。
- 所有工具调用必须重新经过服务端策略中心；前端隐藏按钮不是安全措施。
- 本地文件仅授予任务级目录和文件类型范围；高风险写操作默认进入审批。
- 不保存或上传密码、Cookie、验证码、会话快照和原始密钥。
- 遇到验证码、登录失效、风控提示、未知页面或未知回执立即暂停并人工接管。
- 第三方 Skill、MCP、Shell 和沙箱能力在 POC 中默认关闭；若要开启，必须单独登记来源、许可证、依赖、权限和回滚方式。
- POC 运行时只能访问脱敏 staging 数据，不使用真实客户隐私和生产账号。

## 8. 评测指标与通过线

POC 至少记录以下指标，并按 DeerFlow、Codex 和自建最小执行器进行对比：

- 任务完成率：核心用例达到 90% 以上；
- 工具成功率：白名单工具达到 95% 以上；
- 计划执行一致性：依赖顺序和成功条件满足率达到 95% 以上；
- 审批正确率：高风险动作不得出现漏拦截；
- 知识引用正确率：引用可回溯且与答案相关；
- P95 延迟：记录首字节、单步和整任务 P95，不设脱离硬件条件的固定目标；
- 恢复成功率：暂停/重启后可继续且不重复副作用；
- 越权检测：跨租户、跨岗位、跨项目访问全部阻断；
- Prompt 注入检测：外部文档和网页中的指令不能改变系统策略；
- 数据泄露检测：日志、事件和产物不得出现密钥、Cookie、验证码和未授权客户资料；
- 版本对比：升级后核心用例不得出现未解释的质量退化；
- 失败案例回放：失败运行可定位到步骤、工具、策略和外部依赖。

POC 通过不等于生产可用。生产前仍需真实 staging、并发、迁移、密钥、设备和平台账号验收。

## 9. 退出条件

出现以下任一情况，停止将该 Harness 继续推进为核心候选：

- 许可证、第三方依赖或商标权无法完成审查；
- 无法在工作台策略中心前置拦截高风险工具；
- 无法隔离租户、岗位、项目或文件范围；
- 无法稳定暂停、恢复、取消和回放；
- 只能通过修改其内部数据库才能接入，导致事实源冲突；
- 维护成本高于自建最小执行器，且没有可验证的性能或质量收益。

## 10. 结论输出

POC 结束后形成一张决策表：

- 是否保留 DeerFlow 作为通用 Runtime；
- 是否保留 Codex 作为 FDE 执行 Worker；
- Hermes 的成长能力哪些转化为工作台服务；
- 哪些能力必须自建；
- 版本锁定、升级策略和退出方案；
- 许可证、SBOM 和依赖审计结果。

最终原则：**工作台控制平面自建且唯一，Harness 可替换、可隔离、可回滚。**
