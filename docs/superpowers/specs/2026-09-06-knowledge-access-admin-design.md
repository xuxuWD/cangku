# 知识权限管理台设计规格

## 目标

为超级管理员提供一套中文、易理解、可追溯的知识权限配置界面。管理员可以按岗位或单个数字员工选择知识库访问范围，查看影响对象和近期变更，并在保存前获得明确反馈。

本设计只覆盖管理台首个页面和其前端基础组件，不改变后端权限模型。前端所有数据通过 `/api/v1` 服务端接口获取，浏览器、桌面端和 PWA 不直接访问数据库。

## 视觉方向

采用“浅色轻拟物 + 克制科技色”方向：

- 画布使用浅灰蓝，内容面板使用白色或近白色；避免大面积黑色和紫色渐变。
- 青蓝用于当前选中、主要操作和服务状态；绿色只代表正常/已启用，橙色只代表待确认或敏感提醒，红色只代表错误或危险操作。
- 通过柔和的外阴影和很轻的内阴影表达层次，阴影不承担信息含义，不使用厚重玻璃、金属或 3D 装饰。
- 页面内容优先，不做营销型 Hero，不使用卡片套卡片。知识库采用单个大列表面板，审计记录作为右侧独立区域。
- 正式产品不使用 emoji，也不使用外部线性图标。图标采用统一比例的实心几何图形组件，颜色继承语义色令牌。

## 字体与文字

- 优先使用系统字体栈：`-apple-system`、`BlinkMacSystemFont`、`SF Pro Display`、`PingFang SC`、`Microsoft YaHei`。
- 标题使用 28-30px、700 字重；页面正文使用 13px，行高 1.6；辅助信息使用 11-12px，行高不低于 1.45。
- 所有用户可见文字使用普通员工能理解的中文，如“保存调整”“清空选择”“可以使用的知识库”“这次调整会影响谁”。不暴露程序员术语、接口名、数据库名或英文缩写。
- 长文本允许自然换行，不通过固定高度、强制省略或负字距解决布局问题。

## 页面布局

桌面宽屏采用三段布局：

1. 左侧管理导航，约 220px，显示工作台首页、员工与岗位、知识权限管理、数字员工设置、模型与费用、安全与操作记录。
2. 中间主内容区，使用 `minmax(0, 1fr)`，最大宽度约 1080px，包含页面标题、对象切换、知识库列表和最近一次调整。
3. 右侧审计区，约 288px，显示实时状态、权限变更时间线、提示音设置和影响范围说明。

响应式规则：

- 1080px 以下，右侧审计区移到主内容下方，主内容保持可读宽度。
- 720px 以下，侧栏改为水平滚动导航；审计区变为普通纵向内容；知识库列表保持单列。
- 任何断点都不允许水平滚动主内容，不允许标题、按钮或卡片文字溢出。
- 控件的可点击区域至少 44px 高，移动端不依赖悬停完成关键操作。

## 核心交互

### 对象选择

页面提供“岗位权限”和“数字员工权限”两个分段选项。岗位权限默认选中“自媒体运营岗”，显示部门和员工数量；切换到数字员工权限后，选择器显示具体数字员工及其所属岗位。后续接入 API 时，当前对象由 URL 查询参数或路由状态恢复。

### 知识库授权

知识库以内容驱动高度的列表行呈现，每行包含实心主题图标、名称、普通中文说明和开关。启用状态使用绿色开关和文字状态共同表达，不能只依赖颜色。敏感范围附带“需审批”标签和说明。

默认拒绝：接口未返回授权范围时，前端显示未授权，不推断为全库授权。岗位继承关系通过辅助说明表达，单个数字员工可以进一步收紧范围。

### 保存与清空

- “保存调整”是页面唯一主要操作。点击后按钮进入“正在保存”状态并暂时禁用，成功时显示短暂 Toast“已保存权限调整”，失败时显示原因和“重新尝试”入口。
- “清空选择”属于次要操作。清空前如已有授权，需要确认影响范围；确认后允许通过页面顶部 Toast 撤销本次清空。
- 保存成功后刷新最近一次调整和授权数量；保存失败不改变本地选择，确保用户可重新提交。

### 声音与动效

- 默认开启短促、低音量的成功/提醒音；提供“提示音：开/关”按钮和后续免打扰时段设置入口。
- 动效只表达因果关系：开关按压、保存加载、成功 Toast、审计记录出现。微交互 150-300ms，保存加载不超过 400ms 的视觉循环。
- 支持 `prefers-reduced-motion: reduce`，减少或关闭位移、波形和过渡；声音关闭不影响视觉反馈。
- 后续提供统一声音事件枚举：`success`、`warning`、`error`、`approval`，不在组件内部散落音频逻辑。

## 状态与错误

页面必须覆盖以下状态：初始加载骨架、数据加载成功、未授权空状态、未授权访问、网络异常、保存中、保存成功、保存失败、权限冲突、禁用控件和敏感范围待审批。

错误信息必须说明原因和下一步，例如“权限服务暂时不可用，请检查网络后重新尝试”，而不是只显示“请求失败”。未授权用户不能看到可执行的配置按钮；即使前端隐藏按钮，后端权限校验仍是唯一安全边界。

## API 对接

页面使用现有接口：

- `GET/PUT /api/v1/knowledge-access/roles/{role_key}`
- `GET/PUT /api/v1/knowledge-access/agents/{agent_key}`
- `GET /api/v1/knowledge-access/audits`

请求需要携带当前登录会话。PUT 请求传递明确的知识范围集合和幂等键；前端不得把数据库 ID、访问令牌或原始密钥写入日志。网络请求统一封装，组件只处理加载、成功和错误状态。

## 可复用组件

- `AppShell`：顶栏、侧栏、响应式布局。
- `FilledIcon`：统一的实心几何图标，支持语义色和无障碍标签。
- `SegmentedControl`：岗位/数字员工切换。
- `ObjectSelect`：岗位或数字员工选择器。
- `KnowledgeScopeRow`：知识库名称、说明、敏感标签和开关。
- `SaveButton`：默认、加载、成功、失败状态。
- `NoticeBanner`：敏感资料和错误提示。
- `AuditTimeline`：权限变更时间线。
- `SoundPreference`：提示音开关和可访问性说明。
- `Toast`：保存成功、撤销和错误恢复提示。

组件不直接读取 API，不在组件中写硬编码权限判断；权限能力由页面状态和服务端结果共同决定。

## 验收标准

- 1440px、1024px、768px、390px 宽度下文字、按钮、开关和列表均不溢出。
- 所有卡片/列表行文字上下留白均匀，最小垂直内边距 16px；内容变化不会造成横向跳动。
- 键盘可以访问所有控件，焦点清晰；图标按钮有中文 `aria-label`；状态变化通过 `aria-live` 告知。
- 普通员工、CEO、超级管理员访问页面时展示符合后端权限的操作能力；未授权响应不能被前端绕过。
- 保存重复点击、断网、接口超时和服务端拒绝时不产生重复提交，且用户能恢复操作。
- 开启/关闭声音和减少动效后，所有功能仍可完成；系统不自动播放持续音频。
- 浏览器视觉检查通过后，才进入 React 生产实现；视觉稿不作为生产代码直接复制。

## 不在本阶段

- 不在本页实现任意 Skill 安装、Shell 执行、高权限沙箱或自动修改生产工作流。
- 不在本页实现 GEO 业务流程，只通过已有工作台 API 和后续适配器读取权限结果。
- 不在本页生成岗位主题营销插画。需要主题插画的首页、介绍型智能体和空状态页面另行设计，并在需要时使用 GPT Image 2 生成、审核和压缩资源。
