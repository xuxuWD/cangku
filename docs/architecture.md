# 公司数字员工工作台架构

## 目标

工作台是公司内部数字员工的统一控制平面。Windows 桌面端负责员工日常操作，网页端负责管理和远程协作，手机端负责审批、提醒和紧急处置。所有客户端通过版本化服务端 API 工作，客户端不直连数据库。

## 组件边界

```text
桌面端 Electron + React ─┐
网页管理台 React          ├─ HTTPS /api/v1 ─ 控制平面 FastAPI
手机 PWA                  ┘                         ├─ PostgreSQL + pgvector
                                                    ├─ Redis + Celery
                                                    ├─ 对象存储
                                                    ├─ 模型网关
                                                    ├─ 知识与记忆服务
                                                    ├─ 策略、审批与审计
                                                    └─ GEO 版本化适配器
```

工作台只拥有统一入口、身份、岗位、权限、任务、审批、通知、用量和审计；GEO 仍拥有观测、证据、内容、发布和报告等业务能力。两者使用任务号、项目号、产物版本和证据引用关联，不跨库写入。

## 外部集成的判据：接适配器 vs 搬代码

**默认口径：外部能力一律「接适配器」，不搬代码**（依据：宪法 2.2 职责单一、12.3 许可；本节「发布边界」）。

| | **接适配器（默认）** | **搬代码（例外）** |
| --- | --- | --- |
| 定义 | 对方是**独立进程 / 服务**，我们只按 `AgentRuntimeAdapter`（`app/runtime/contracts.py`）与 HTTP 边界调用（`app/runtime/adapters/common.py` 的 `HttpRuntimeTransport`） | 把对方源码 fork / vendor / copy 进本仓库，直接函数调用 |
| 我们能看到 | 对方**暴露的接口面** | 全部实现 |
| 升级 | 换**钉死版本**即可 | 跟上游，或**永久分叉** |
| 漏洞 | 上游修 | **自己修** |
| 影响面 | 限于适配器模块 | 进入我们的进程与依赖树 |

**三问判据**（任一为「否」即走适配器）：

1. 我要的是**能力**，还是**它的代码**？
2. 它是不是**进程 / 服务级**能力（而非内部实现细节）？
3. 若真要搬：**许可可商用？无状态窄组件？进程边界传不过去？我们愿意长期维护？**

**第三种模式：只读研读（连接都不接）**

当许可为**非商用 / 强传染**时，**连"接适配器"也不行**——把别人的软件跑起来就是"使用软件"，对营利业务系统即构成商业使用 = **违约**。此时唯一安全路径是：**只读源码、提炼设计、自己实现**（**思想与架构不受版权保护，源码才受**）。

| 模式 | 何时用 | 样本 |
| --- | --- | --- |
| ① 接适配器 | 许可宽松 + 进程/服务级能力 | DeerFlow / Codex / Hermes / `dsh` |
| ② 搬代码（严格例外） | 许可宽松 + 无状态窄组件 + 进程边界传不过去 | **无已生效实例**；**唯一候选**：OpenClaw 的 `computer-use` 脚本集（MIT，**未评审、未启用**，判据见 [`docs/moat-boundaries.md`](moat-boundaries.md) §3） |
| ③ **只读研读（连接都不接）** | **非商用 / 强传染许可**，或只想要"设计" | **EvoFlow、OpenWorkBuddy**（PolyForm Non-Commercial）——**不进运行链路、不进仓库** |

**一类明确不可搬的（硬约束）**：把「**用户本机 CLI 当引擎 / 单机单用户**」形态的 harness 搬进来，会带进**第二套用户、权限与审计**，并与本节「发布边界」「自动化与权限」冲突。

**现有外部集成的落地方式（对照）**：GEO / WeKnora / RAGFlow / AgentScope / DeerFlow / Codex Worker / Hermes 全部为**适配器 + 独立进程**，**无一搬代码**；dsh 同此口径（段二规格：dsh 细节封在适配器内部，其类型**不得**进入本项目领域模型）。

> **代价要说清**：不搬代码换来的是「**能力面 = 对方接口面**」。若所需能力在接口面之外，只有三条路——① **自研**（首选）、② 推动对方开放接口、③ 接受「引进第二个平台」的代价（会引入第二套用户/权限/审计，通常最贵）。

> **接入之后怎么共存**：见 [`docs/multi-adapter-coexistence-spec.md`](multi-adapter-coexistence-spec.md)（六条不变量、能力矩阵、职责归口表、冲突处理规则与待裁决项）——本节管"要不要接"，该规约管"接了之后不打架"。

> **参考（**非强制入口**）：两张表**——[`docs/moat-boundaries.md`](moat-boundaries.md)（**哪些层绝不允许外包** + "缝合怪"自检清单）与 [`docs/capability-ownership-map.md`](capability-ownership-map.md)（**每个能力的归属**：自研 / 用轮子 / 接适配器 / 只读学）。**"要不要自研、要不要搬、要不要接"这类问题可先查表作参考；查不到的能力，建议先补表再动手**（同一能力只允许一个归属）。**J-13 更正**：原为祈使句"动手前先查表…先补表再动手"，与下方状态声明（三份文档**未评审**）**相冲突**，已改为参考措辞。
>

## 客户端

- `admin-web/`：网页管理台（React + Vite），面向管理和远程协作。
- `companion-pwa/`：手机 PWA 伴侣端（React + Vite，手写 service worker），只做登录、待办与审批；提醒为**轮询式**（非 Web Push）。
- `desktop/`：Windows 桌面端 Electron 安全壳，加载网页端界面；打包与签名尚未验收。

三端都只调用版本化 `/api/v1`，不直连数据库；「待我审批」由 `GET /api/v1/approvals/pending` 按角色聚合（任务审批、计划提案、账号注册）。

事件总线按存储模式选择：开发环境使用内存总线验证接口流程；PostgreSQL 模式使用 Redis Streams，任务事务只写 Outbox，Celery Worker 负责发布，API 进程不再重复直发事件。

企业知识服务通过版本化适配器接入 WeKnora。工作台只向适配器传递当前租户、岗位允许的知识库范围和查询文本，适配器返回带来源的引用片段；客户端不直连 WeKnora 数据库，也不能自行指定未授权知识库。WeKnora 的 Skill、Shell、沙箱和自动写入能力默认关闭，真实 staging 接入前不视为生产可用。
> **知识归口（D1，2026-09-15 用户拍板）**：企业知识检索**唯一主源 = WeKnora**；RAGFlow 降为对照/实验（默认关闭，不参与生产工具面）。见 `capability-ownership-map.md` §4 / `multi-adapter-coexistence-spec.md` §4/§8。

RAGFlow 仅作为知识层**对照/实验**适配器提供带引用的租户内只读检索（D1 后默认关闭、不参与生产工具面），知识库范围由工作台服务端上下文解析并校验。AgentScope 仅作为受控执行器承接运行、事件和人工确认；两者都不能直连工作台数据库，也不能决定审批结果、任务最终状态或其他控制平面事实。
> **执行归口（D2，2026-09-15 用户拍板）**：真实工具/命令执行**唯一路径 = dsh**（挂九步闸门 + 隔离容器 + 授权位 027）；Codex Worker 仅承接 FDE 交付（受限文件范围，非升权执行）；AgentScope 降为实验（不入生产工具面）。见 `capability-ownership-map.md` §4 / `multi-adapter-coexistence-spec.md` §4/§8。

知识库范围由租户级注册表维护，分别支持岗位和数字员工绑定。普通员工检索时由服务端自动解析范围并再次校验租户；空范围默认拒绝，不因 WeKnora 或客户端参数缺失而回退到全库。

生产环境的岗位/数字员工绑定写入 PostgreSQL `004_knowledge_access_bindings.sql`，开发环境才允许使用进程内注册表；绑定变更保留操作者并在事务内替换旧范围。

每次范围替换同时写入 `005_knowledge_access_audit.sql` 审计表，记录旧范围、新范围、操作者和时间，供超级管理员排查权限变更；审计记录不作为客户端可修改配置。

## 核心领域对象

租户、组织、用户、岗位、设备、数字员工、技能、提示词版本、模型、路由策略、知识库、文档版本、记忆、任务、运行、步骤、产物、审批、授权、发布回执、用量和审计事件。

**落地状态（2026-09-12）**：已有实体表的是租户/工作区、账号与单点身份、任务与审计事件、知识范围绑定、运行记录与运行状态、站内通知、审计日志、**用量账本**（`workbench_usage_ledger`，追加式 + 冲正，供管理台「用量与费用」页只读展示），以及**岗位与数字员工目录**（迁移 `022_workforce_directory.sql`：数字员工必须归属一个岗位，复合外键 `(tenant_id, role_key)` 把租户隔离写进约束；标识创建后不可改，停用只改状态、不删除，以保证历史任务与知识绑定仍可解析）。组织与部门、设备、技能、提示词版本、模型与路由策略**尚无实体表**——模型来自配置注入的 `ModelGateway`，Runtime 来自受控配置注册表。另新增**对话层与数字员工配置**（迁移 `023_conversational_agent.sql`）：`workbench_conversations` 持有租户语义，`workbench_conversation_messages` 为 append-only；`workbench_digital_employees` 追加提示词 / 模型 / 温度 / 技能白名单 / 记忆策略与员工级治理字段（自治等级、风险阈值、审批超时、每日预算），配置读写仅 `super_admin`。P1 的对话使用确定性桩回复（`MockRuntime`），**不执行任何真实工具**；文件读写与命令执行属 P2（D8）。

## 自动化与权限

所有动作由服务端策略中心重新判定：用户、设备、租户、项目、数据范围、动作、外部目标、预算、审批状态、授权有效期和幂等键必须同时满足。高权限数字员工表示高自治，不表示无限权限。

低风险动作可以自动执行；外部草稿、授权范围内的提交等动作需要短期授权；公开发布、删除、权限、费用和不可逆动作必须再次确认。

高风险能力统一经过能力策略中心：第三方 Skill 安装、Shell 执行、特权沙箱、企业知识写入、岗位提示词修改和生产工作流修改默认进入审核状态。只有经过专用灰度流程并满足环境、范围、预算和回滚条件后才能放行；单次管理员批准不能直接绕过这些条件。

## 记忆与成长

记忆按企业、部门、岗位、项目、用户和任务范围隔离。临时变量、结构化业务数据、任务经历、用户偏好和长期语义记忆分别管理。成长服务只生成候选技能、提示词和记忆提案，经过测试、管理员审核、小范围试用后才可启用，并保留回滚版本。

## 事件失败处理

事件超过有限重试次数后进入死信记录，保存租户、事件载荷、失败原因、尝试次数和重放审计信息。Outbox 发布器达到尝试上限时会自动写入该记录，避免失败事件只停留在 Outbox。CEO 或超级管理员才能查看和发起重放；重放仍回到原事件总线，由消费端幂等处理。开发期提供内存实现，生产使用 `003_dead_letters.sql` 对应的 PostgreSQL 表，未完成 staging 联调前不标记为生产可用。

RAGFlow 与 AgentScope 的开发期适配器和受控注册表只证明协议边界可测试；真实服务部署、认证注入、跨租户实测、并发压测、沙箱验证和 staging 验收仍未完成，不能据此宣称生产可用。

## 发布边界

优先使用官方 API；无官方 API 时使用用户本人登录的本地授权助手；无法确认授权路径时只提供人工交付内容包。系统不保存密码、Cookie、验证码或会话快照，也不实现私有接口模拟、风控规避、设备伪装和代理轮换。
