# 故障手册

> **适用范围**：本手册面向**客户方管理员**与**平台运维**，用于「先自己把问题定住、再决定要不要找平台方」。
> 员工侧自助排查见[《员工手册》](employee-handbook.md) §10；部署、监控与回滚的完整操作见
> [`private-deployment-runbook.md`](../private-deployment-runbook.md)。
>
> **口径**：本手册只写**已交付**的排查动作与**已存在**的信号。凡「规则已定但渠道未接入」的，
> 一律标注（见 §5），**不得读作「已接监控」**。

## 1. 三条纪律（先看这个，能省掉一半沟通成本）

1. **报错原文一个字都别改**。截图或复制文字，不要转述成「它说连不上数据库」。
2. **不要用「删掉报错 / 关掉检查」的方式让问题消失**。也不要为了「先跑起来」加一层把异常吞掉的兜底——
   那会把故障从「立刻可见」变成「数据悄悄错」。
3. **同一问题连续三轮没解决就停手**，换人 / 换环境重查，而不是继续试。
   一轮 = 提出原因 → 按该原因改一次 → 重走原来出错的流程仍然失败。

## 2. 现象 → 自助排查（客户侧可做，全部只读）

| 现象 | 先确认 | 结论怎么读 |
|---|---|---|
| 所有人都登录不上 | `GET /api/v1/health` 是否 200 | 非 200 ⇒ 应用入口不通，跳到 §3 采集；200 ⇒ 看下一行 |
| 只有个别人登录不上 | 是否提示「登录尝试过于频繁」 | 是 ⇒ 限流保护，等 5 分钟窗口过去再试；不是 ⇒ 确认账号是否已审批、动态验证码是否过期 |
| 页面能开但操作都失败 | 浏览器开发者工具里的 HTTP 状态码 | `401` 会话失效（重新登录）；`403` 角色权限（对照[《客户管理员手册》](customer-admin-handbook.md) §9）；`503` 服务依赖不可用 |
| 数字员工「不回复」 | 打开该对话看右侧过程与事件时间线 | 卡在某一步 ⇒ 记下步骤与时间；一直无进展 ⇒ 见 §4「运行长时间不结束」 |
| 任务一直是「运行中」 | 「运行详情」的事件时间线最后一条时间 | 长时间不推进 ⇒ 先「暂停 / 取消」止损，再按 §3 采集 |
| 收不到通知 | 通知页是否为空、伴侣端是否只是没刷新 | 伴侣端提醒是**定时刷新**不是系统推送；先手动刷新确认 |
| 审批卡不出现 | 运行是否已到需要拍板的那一步 | 没到 ⇒ 正常；到了仍不出现 ⇒ 记下运行编号按 §3 采集 |
| 用量一直是 0 | 本租户是否真的产生过用量 | 没有用量记录时页面会如实说明，**不是出错** |
| 导出包下载不了 | 包是否已过期（7 天） | 过期返回「导出包已过期」；需要就重新申请一次导出 |
| 磁盘吃紧 | 宿主磁盘使用率 | ≥80% 预警、≥90% 严重（规则见 runbook「监控与告警」第 7 条） |
| 导出 / 删除作业不动 | 后台周期任务是否在派发 | 调度停 ⇒ 周期任务全停（导出、删除、到期扫描都不跑），跳到 §3 |

## 3. 需要平台方介入时：请带上这四样

1. **报错原文**（不改字，含状态码与接口路径）
2. **发生时间**（大概到分钟，以及是否仍在持续）
3. **影响谁 / 影响多大**（单用户 / 单岗位 / 全租户；是否影响写入）
4. **出问题前动过什么**（改过配置 / 迁移过 / 重启过 / 刚导入过知识 / 刚跑过导出或删除）

同时请附上**只读采集**的结果（二选一，均可脱敏后回传）：

- **一键探针**：`py scripts/monitoring_probe.py`——按 9 条规则输出判定与默认阈值；
  **信号不可用时会显式 `skipped` 并写明原因，不会静默算作通过**。
  退出码：`0` 全 `ok` / `skipped`、`1` 存在 `alert`、`2` 参数或配置错误。
  默认拒绝 `http://` 与 localhost 目标（需显式 `--allow-insecure` / `--allow-local`）。
- **客户侧验收探针**：`py scripts/customer_acceptance_probe.py`（配套清单
  [`customer-side-acceptance-runbook.md`](../customer-side-acceptance-runbook.md)）。

> **红线**：平台方**不得直接连生产边查边改**——只给只读命令，由客户侧执行后回传结果。

## 4. 四类高频问题的定位路径

### 4.1 「异步的东西都不动」（导出包不生成、到期扫描不跑、删除不执行）

后台任务由**调度进程（beat）+ 执行进程（worker）**驱动，两者任一停摆都会表现为「异步功能全静默」。

- 判定顺序：① 调度是否在派发（日志里 `Sending due task` 是否断档 ≥5 分钟）；
  ② worker 容器健康检查是否 `unhealthy`；③ 事件队列是否积压。
- **不要**用「把周期任务改成长间隔」来掩盖：那等于事实停用。

### 4.2 运行长时间不结束

- 先看事件时间线的最后一条与时间戳，判断是「卡在工具调用」还是「卡在等审批」。
- 「等审批」是正常态：审批集中在 CEO / 超管，若无人可批（例如单管理员部署下你自建的任务）会一直等
  ⇒ 需要预留第二名审批人（见[《客户管理员手册》](customer-admin-handbook.md) §3.2）。
- 止损用「取消」（不可撤销）；要保留现场就先「暂停」。

### 4.3 登录 / 会话类

- `401`：会话过期或已被撤销（登出即撤销，不靠过期兜底）。重新登录即可。
- `403` 且文案含「动态口令」：管理员被要求强制绑定 TOTP，未绑定前只有受限会话，
  只能访问绑定 / 确认 / 登出 / 健康检查。
- `503` 且文案含「会话密钥」：部署侧会话密钥未配置或不可用——属配置问题，不是账号问题。
- 撤销存储不可用时登出会返回 `503`（**fail-closed，绝不放行**）——这是刻意行为，不要「修」成静默成功。

### 4.4 数据与合规类

- **审计查不到刚发生的事**：先确认是否有业务流量；审计长时间不推进本身是告警项（runbook 第 6 条）。
- **导出包里少了内容**：先看包内的 `unimplemented_categories`（4 类无实体，属已知）、
  `unavailable_categories`（读取失败）、`truncated_categories`（超 5000 行上限）。
  这三处都是**如实标注**，不是丢数据。
- **删除租户没执行**：删除要三项前置齐备（冷静期结束 + 已完成最终导出 + 已记录确认人）；
  缺任一项都会被拒。到期未显式确认时后台会**按申请自动确认**并写审计。

## 5. 监控与告警的现状（如实）

- **9 条规则的判定与默认阈值已确定**（beat 派发 / worker 健康 / app 健康 / 事件积压 / 死信新增 /
  审计是否在落 / 宿主磁盘 / 数据库连接数 / worker 资源），并已落成**只读探针**。
- 🔴 **告警渠道尚未接入任何环境** ⇒ **目前没有人会收到自动告警**；
  「规则写在手册里」不等于「告警已生效」。接入方式三选一（客户既有监控平台 / 宿主侧采集脚本 + 邮件或 webhook /
  云厂商自带告警），**接入后必须真实触发一次验证**，并写入客户交付记录。
- 已生效的**有界性**措施：容器日志已设上限（`json-file` / `max-size=10m` / `max-file=5`，三服务）；
  运行事件按保留期清理（默认 30 天）。**审计不清理**（不可篡改口径）。

## 6. 恢复与回滚（只引用，不另立口径）

- 恢复**必须先在隔离数据库演练**，验证备份可读、对象索引一致、租户隔离与审计可查询。
- 恢复通过后，**维护窗口内停止写入**，把应用版本与数据库恢复到**同一已验证组合**。
- 回滚**只使用已演练的数据库备份与对象存储清单**；**禁止手工修改用量账本或审计记录**。
- 恢复完成后重新执行预检、冒烟测试与权限测试，并记录**操作人 / 时间 / 原因 / 结果**。
- ⚠️ **未验收**：迁移回滚演练与「真跑一次恢复」**尚未在客户环境执行**（属交付清单组 1），
  因此**当前不能承诺恢复时长（RTO）**。

## 7. 明确不做 / 未验收（避免误判为故障）

| 项 | 说明 |
|---|---|
| 手机端系统推送 | 提醒是**轮询**，不是 Web Push ⇒ 「手机没弹通知」不算故障 |
| 桌面端自动更新 | 「旧版 → 新版」链路**未在干净机器验收**；安装包**未签名** |
| 自动化调度（定时跑任务） | **尚未交付** |
| 任务中心的列表 / 详情页 | **尚未交付** |
| 保留策略的自动清理 | **无服务端执行器**（见[《客户管理员手册》](customer-admin-handbook.md) §8.1） |
| 真实模型 / 抓取 / 公众号发布 | 取决于部署配置；**未用真实账号验收** |
| C1 电脑控制 / C2 浏览器操作 | **未立项** |

## 8. 升级路径与联系

1. **L1（客户管理员）**：按 §2 自助排查 + §3 采集四样信息。
2. **L2（平台运维）**：按 §4 定位，必要时在维护窗口执行 §6。
3. **L3（研发）**：带齐 §3 四样信息 + 探针输出 + 相关时间窗口的日志片段（脱敏）。

联系人与响应时间请在**客户交付记录**里填写（本手册不预置联系方式，避免过期信息被当真）。
