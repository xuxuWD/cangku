# 客户管理员手册

> **适用范围**：本手册面向客户方的**超级管理员 / CEO / 客户管理员**（角色 `super_admin` / `ceo` / `customer_admin`），
> 覆盖「上线初始化 → 账号与权限 → 岗位与数字员工 → 知识与技能 → 用量与合规 → 数据导出与租户删除」。
> **普通员工的操作**见[《员工手册》](employee-handbook.md)；**出故障怎么办**见[《故障手册》](troubleshooting-handbook.md)。
>
> **口径**：本手册逐条对应**已交付**的后端能力与界面。**后端已交付但管理台还没有界面入口**的能力
> 会明确标注（按纪律不摆假按钮）；凡尚未交付或未在真实环境验收的，一律在 §9 如实列出。

## 1. 上线后第一件事：建立首个管理员

账号体系是**自建 + 审批制**：员工提交注册申请，管理员审批并**指定角色与归属租户**，审批通过后才能登录。

首个管理员由部署方注入一次性初始化口令（`WORKBENCH_BOOTSTRAP_TOKEN`）：

1. 部署方在配置里注入初始化口令（**不进仓库**）。
2. 你用它提交**首个管理员申请**：角色固定为超级管理员，租户由申请自行声明；
   口令不正确会返回 `403`，因此这一步同时验证了部署配置是否正确。
3. 之后所有普通申请的 `tenant_id` 与 `role` **一律忽略**——角色只能由审批人指定，申请人无法自封。

> **口令策略**（注册、本人改密、管理员重置三条链路统一实施，**不可通过环境变量关闭**）：
> 长度 10–128、非纯数字、非重复单字符、不得命中内置常见弱口令集合。
> **已知限制**：不做变形归一（对已收录口令追加字符或冷门变体不会被拦截），也不校验是否含本人手机号/姓名。

## 2. 账号与登录安全

### 2.1 审批注册申请

- 管理台「安全与审计」以外的入口：注册审批走接口 `GET /auth/registrations?status=pending`（仅超级管理员）
  与 `POST /auth/registrations/{id}/approval`（请求体 `role` + `tenant_id`）、
  `POST /auth/registrations/{id}/rejection`（请求体 `reason`）。
- 只允许审批 `pending` 状态：**重复审批返回 `409`**，账号不存在返回 `404`，非超级管理员返回 `403`。
- 申请列表里的手机号是**脱敏**的（例如 `137****0001`）。

### 2.2 登录保护（已生效，无需配置）

| 机制 | 行为 |
|---|---|
| 口令存储 | 只保存 **scrypt 哈希**；任何响应、事件、日志都不含口令或哈希 |
| 登录限流 | 同一手机号 5 分钟窗口内失败达阈值 ⇒ `429`「登录尝试过于频繁」；**已存在与不存在的手机号表现一致**，不泄露账号是否存在 |
| 失败提示 | 手机号不存在 / 口令错误 / 未审批**统一**为「手机号或密码不正确」 |
| 登出 | 把令牌唯一号记入**服务端撤销名单**，同一令牌**立即失效**（不靠有效期兜底）；撤销存储不可用时 `503` fail-closed，绝不放行 |

### 2.3 动态口令（TOTP）二次验证

- 管理员（`super_admin` / `ceo`）可被要求强制绑定动态口令（`WORKBENCH_REQUIRE_ADMIN_TOTP`）。
  未绑定前签发的是**受限会话**：只能访问绑定 / 确认 / 登出 / 健康检查，
  访问其他接口一律 `403`「账号需要先完成动态口令绑定」；受限会话有效期默认不超过 300 秒。
- 动态口令种子在持久化层**静态加密**（AES-256-GCM + HKDF 子密钥，密文带 `v1:` 前缀）。

## 3. 岗位与数字员工

### 3.1 两个页面分工

| 页面 | 性质 | 用途 |
|---|---|---|
| **员工与岗位** | **只读**名册 | 有哪些岗位与数字员工、各自能看到哪些知识范围、关联了多少任务；顶部横幅提示「待我审批」 |
| **数字员工设置** | 可写 | 岗位与数字员工的增改、启停，以及每个数字员工的执行参数 |

> 要改配置就去「数字员工设置」或「知识权限管理」——「员工与岗位」页不做增删改。

### 3.2 数字员工的执行参数（逐项含义）

| 参数 | 含义 |
|---|---|
| 系统提示词 | 这个数字员工的角色与做事口径 |
| 模型 | 用哪个模型（由部署配置提供可选清单） |
| 温度 | 输出的发散程度 |
| 可用工具白名单 | 它**被允许**调用哪些工具；白名单外一律拒绝 |
| 记忆策略 | 短期记忆是否开启、保留几轮 |
| 自治等级 | 哪些步骤需要人工拍板（如「高风险才审批」/「全程自动」） |
| 风险阈值 | 达到该风险档就必须走人工审批 |
| 审批等待 | 审批等待超时（分钟） |
| 每日预算（**整数分**） | 该员工的每日成本上限；页面上按「元」输入，提交前换算为分 |

- **改动会写入审计**；不符合要求时保存会**就地给出原因**（例如非整数、负数）。
- **发起人不得审批自己发起的事**：单管理员部署下，你自建的需审批任务需由另一名 CEO / 超管审批，
  否则无人可批——这是有意的治理约束，请在配置里预留第二名审批人。

## 4. 知识：谁能看到什么、什么样的知识能被检索

### 4.1 知识权限管理

- 按**对象**（岗位 / 数字员工）勾选**可见的知识范围**；数字员工检索时**只会在勾选范围内找资料**。
- 改完立即生效，并留下审计记录（旧范围 / 新范围 / 操作者 / 时间）。
- 保存失败会给出原因；不确定当前值就点「刷新」重读服务端值。

### 4.2 知识治理（文档生命周期）

文档状态机：**草稿 → 已发布 → 待复核 → 已归档**（任意状态都可归档）。

- **未登记的文档默认不可检索**——这是有意的：先登记（谁拥有、什么状态、何时复核），再允许被用。
- **检索前有治理过滤**：已归档 / 待复核的文档会被排除在检索条件之外；
  过滤**fail-closed**：可检索集合为空时**直接返回空结果，不发起上游检索请求**。
- 到期复核由后台周期扫描自动把「已发布且过复核期」的文档置为**待复核**（默认每小时扫一次）。
- **检索是唯一生产路径**：`GET /api/v1/knowledge/search`，**仅超级管理员可访问**；
  服务端从登录上下文解析租户与知识库，客户端**不得自带租户 / 知识库参数**。
- 检索响应**必须带原因归属**；**查询原文不写入审计**（只记结论）。

### 4.3 技能（Skill）

- 技能包遵循 **SKILL.md 开放标准**；提交后进入**人工复核**，复核通过才能启用。
- **白名单 + 人工复核**是硬要求（防止技能包投毒）；启用 / 禁用都写审计。
- 审计只记技能键、版本、来源与员工标识，**不记包正文与描述**。

### 4.4 记忆

记忆分三层，治理口径不同：

| 层 | 形态 | 治理 |
|---|---|---|
| 身份 | 键值对，常驻 | 随会话上下文常驻 |
| 规则 | 需**人工复核**，变更走 supersede（旧版被取代而非覆盖） | 未复核不生效 |
| 事实 | 向量检索 | 按租户隔离；写入有每日成本熔断 |

> 记忆层数据**不出内网**；Embedding 用自部署模型，维度固定 1024。

## 5. 用量与费用

- 页面：左栏「用量与费用」。显示本租户**累计用量**与**累计费用**。
- **金额口径：整数分**。账本是追加式的，冲正会写一条负值记录并指向原条目，
  因此累计可能为负；**没有按时间 / 模型 / 任务的维度**。
- **数字为 0 不等于出错**：可能本租户还没有用量记录；页面会如实说明。
- 权限：超级管理员，或**本租户已登记的客户管理员**；其他角色 `403`。
  本租户未在商业化模块登记时返回 `404`「租户不存在」——这是未初始化环境的常见态。

## 6. 数据导出（合规留档）

**界面已接入**（「用量与费用」页的「数据导出」区）：

1. 点**申请导出** ⇒ 服务端只创建**异步作业**并返回 `202`（不在请求线程生成）。
2. 后台生成完成后，在**导出包列表**里出现该包（元数据：包号 / 所属作业 / 生成时刻 / 过期时刻）。
3. 点**下载**取回脱敏载荷（浏览器直接落盘）。

规则与边界：

- **过期时间 7 天**（`expires_at = 生成时刻 + 7 天`）；列表会如实包含**已过期但尚未被清理**的包，
  这类包下载会返回 `404`「导出包已过期」；过期包由后台周期任务物理清理。
- **永不列出 / 取回他租户的包**；跨租户与不存在统一返回 `404`（不泄露他租户资源是否存在）。
- **导出内容脱敏**：不导出密码、Cookie、验证码、令牌、原始 API 密钥或客户原文。
- **15 类里 11 类已接线**（岗位 / 数字员工目录 / 知识文档元数据 / 审计 / 运行 / 记忆 / 任务 / 用户 / 用量 /
  产物 / 步骤）；**4 类无实体或没有按租户读取通道**（知识版本、知识引用、成长提案、审批历史）
  ⇒ 一律**空数组**并在 `unimplemented_categories` 里列出，**不造数据**。
- **「记忆」是整层三类**：每行带 `kind` 字段区分 `fact`（事实）/ `rule`（规则，含 `rule_key` 与 `version`）/
  `profile`（身份类画像 KV）——与删除时的「整层清场」口径一致（此前只出事实类）；
  事实与规则**只出当前生效（active）条目**，已被新版本取代的历史版本不入包。
- 单类**行数上限 5000**，超出**不静默截断**：会在 `truncated_categories` 里给出「取了多少 / 共多少」。
- 某类读取失败时**不写入结果**，只登记在 `unavailable_categories`（与「读了但是空」区分开）。

## 7. 租户数据删除（两步流程）

> ⚠️ 删除是**不可逆**的。执行前请确认已完成最终导出。

1. **申请删除**：接口 `POST /api/v1/commercial/deletion-requests`（仅管理员）。
   申请后进入**冷静期（默认 7 天）**，期间可**撤销**（`POST .../deletion-requests/cancel`，租户回到正常态）。
2. **生成最终导出**：删除申请之后**首次完成**的导出即「最终导出」（服务端据此置位）。
3. **记录确认人**：`POST .../deletion-requests/{job_id}/confirm`——**只有冷静期内且已完成最终导出**才能确认；
   确认本身**不改作业状态**，只是把「谁确认了」记下来（写入审计）。
4. **执行删除**：冷静期结束 + 已完成最终导出 + 已记录确认人，三项齐备后由后台任务执行：
   租户状态推进到**已删除**，并**物理清场**当前已接入的四面数据——**会话层、记忆层、技能层、知识治理层**；
   审计里如实记录**本次实际清到了哪几面**。
   - 每一面都是**整层清场**：会话层 = 执行幂等 / 流帧 / 流状态 / 成员 / 消息 / 会话六张表，
     记忆层 = 事实 / 规则 / 身份类画像三张表，技能层 = 技能包 / 数字员工绑定两张表，知识治理层 = 知识文档。
     **尚未接入清场的面**（任务与运行、CRM、账号、收件箱、知识访问授权绑定等，以及对象存储文件、
     向量索引、缓存）仍会保留，属后续专项——**删除前后请按需自行备份**。

- 三项前置**缺一即拒**（不会静默跳过）；确认与执行**都必须可审计**，没有审计通道时拒绝执行。
- 若到期时管理员尚未显式确认，后台会**按申请自动确认**（确认人 = 请求人）并写同一条审计，
  避免长冷静期导致删除静默卡死。
- **审计记录不随租户删除**：删除动作本身也会写审计。

## 8. 保留策略与审计

### 8.1 保留策略（**已由后台按策略自动执行**，2026-09-19 起）

- 默认保留口径：**任务与运行 180 天、事件与用量 365 天、审计 730 天**；
  可通过接口为租户**缩短**期限（延长需明确配置与存储评估）；**任何保留策略变化都写入审计**。
- **未自定义策略的租户同样按默认口径清理**（默认保留期是平台声明，不是可选项）。
- 执行方式：后台周期任务（默认每小时一轮）**逐租户**清理，每面每轮有上限、剩余留到下一轮；
  **没有**「立即全量清理」入口（只按龄、按轮次）。每轮**确实清了东西**才写一条审计
  `commercial.retention.purged`（动作码在审计页显示为「过期数据已按保留策略清理」，明细含各面行数与结转金额）。
- 逐面口径（**请连同代价一起告知同事**）：
  - **任务（180 天）**：超期任务被物理删除。⚠️ **任务的事件流（任务审计事件）随任务一起消失**。
    若该任务还有没超期的运行，本轮会**跳过**它（避免留下「没有主任务的孤儿运行」），下轮再删。
  - **运行（180 天）**：超期运行的记录被删除。⚠️ **运行域证据不保留、不可恢复**——
    工具执行证据、人工验收决议、运行→任务沉淀链接、产物登记都随运行一起销毁。
  - **用量（365 天）**：**不丢总额**——超期明细会先被**结转成一行净额**（`reason` 标记为
    `retention_carryover`，导出包里可辨认），再删除明细 ⇒ 累计用量与累计费用**逐分不变**；
    但**按时间窗**自行汇总的报表在窗内会因结转而位移（以结转后的明细为准）。
  - **事件（365 天）**：实际保留期取**更短者**——运行事件已按部署参数
    `WORKBENCH_RUNTIME_EVENTS_RETENTION_DAYS`（默认 30 天）清理。
  - **审计（730 天）**：**不清理**——审计按「不可篡改」口径设计，**没有删除路径**（这比 730 天更长，方向安全）。
- 需要长期留档的材料（例：某个任务的审批与运行证据），请在到期前**用导出包下载留档**
  （导出包 7 天后不可取回）。

### 8.2 审计查询

- 页面：左栏「安全与审计」（只读台账，不改动任何业务数据）。
- 可按时间、操作人、对象等条件组合筛选；点开一条看明细。
- 明细走**键名白名单**：未声明的字段一律拒绝写入；工具类动作的取值另有**枚举校验**（不落自由文本）。
- 手机号等敏感列在落库时**已是掩码列**。

## 9. 未交付 / 无界面入口（如实说明）

| 能力 | 现状 |
|---|---|
| 租户删除的**申请 / 撤销 / 确认** | **后端已交付**，管理台**暂无界面入口**（按纪律不摆假按钮）；需由接口调用 |
| **保留策略设置** | 后端已交付、无界面入口（按纪律不摆假按钮）；**执行器已交付**并按默认/自定义策略自动清理（见 §8.1） |
| **自动化调度**（把任务设为定时跑） | **尚未交付** |
| **任务中心的列表 / 详情页** | **尚未交付**；沉淀出的任务有编号，可在审计与运行详情里追溯 |
| **C1 电脑控制 / C2 浏览器操作** | **未立项**（明确不做，避免引入第二套出网归口） |
| 真实模型 / 网页抓取 / 公众号自动发布 | 是否启用取决于部署配置；**未用真实账号验收** |
| 生产环境整体验收（预检、并发压测、备份恢复演练） | **未做**，见交付清单组 1 |

## 10. 日常巡检建议（每周 10 分钟）

1. 「安全与审计」按时间倒序扫一遍，关注登录失败、权限拒绝、删除 / 导出类动作。
2. 「用量与费用」看累计用量与费用趋势。
3. 「员工与岗位」看「待我审批」横幅是否积压。
4. 「知识权限管理」确认新同事已纳入知识范围。
5. 确认导出包已按需下载留档（7 天后不可取回）。
