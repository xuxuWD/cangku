### E-01 【P1】全站**零帮助入口**：没有「帮助 / FAQ / 使用指南 / 关于 / 反馈」

| 字段 | 内容 |
| --- | --- |
| 模块 / 页面 | 全局（管理台 + 伴侣端 + 桌面端） |
| 用户角色 | 全部，尤其**首次使用者** |
| 问题 | 三个客户端**都没有任何帮助入口**。管理台实测整页按钮为：6 个分组标题 + 浅色/深色/跟随系统 + 新建会话 + 导出我的数据 + 刷新 + 展开过程与运行 + 全部/进行中/已归档 —— **没有任何一个指向帮助、教程、FAQ、关于或反馈**。 |
| 复现步骤 | ① 打开 `http://127.0.0.1:5180/` ② 枚举页面全部按钮与链接 ③ 全站检索帮助类关键词 |
| 实际结果 | 帮助类关键词在 `admin-web/src`、`companion-pwa/src` **零命中**；桌面端 `desktop/src` 仅命中 `autoHideMenuBar: true`（菜单栏被隐藏），**未搜到托盘 / 应用菜单 / 全局快捷键接线** |

| 工作量 | 中 |
| 依赖 | 需先定帮助内容的载体（内置 vs 外链文档） |

## 7. 本批小结

- **P0 = 0**；**P1 = 2**；**P2 = 8**。
- **两条 P1**：① **全站零帮助入口**（三端都没有）；② **对话页 6 处开发者文案直接给用户看**。这两条正好对应你最在意的两件事 —— "不能按程序员思维开发" 与 "要有问号/教程"。
- **三处系统性根因**：
  1. **开发视角文案泄漏**（D-01～D-03、D-07 同源）；
  2. **术语未定稿导致混用**（D-04）；
  3. **完全没有帮助体系**（E-01～E-05 同源，不是"做得不好"而是"没有"）。
- **本批最有价值的正面发现**：CRM 那几条文案（G-08 / G-09 / G-12 / G-13）说明**团队是有能力写好人话文案的**，问题出在**对话页与设置页这些"内部视角很重"的地方**，以及**完全没有帮助体系**。这是好消息——不是能力问题，是意识与规范问题。
- **建议顺序**：先定 §4.1 术语表（半小时的活，解开 4 条问题），再立帮助体系（E-01～E-05 一次做完），最后做首访引导。
